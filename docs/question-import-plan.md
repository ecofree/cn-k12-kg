# 外部题库接入总体规划

> 目标读者：我自己 + 用户。写这份文档的原因是：上一轮我直接开始写映射脚本，
> 但「把题加进来」这件事有四个没定清的岔路口，选错了后面全要返工。

---

## 一、先把目标说清楚

用户的原话是「调研全国中高考题目，并开始加入」。这里其实混了两个不同的目标：

| 目标 | 含义 | 成本 | 对诊断的价值 |
|---|---|---|---|
| **A. 收真题** | 每年每地区的中考/高考卷，带年份、地区、卷别 | 高（PDF/OCR/人工） | 低——诊断不关心哪年哪地 |
| **B. 补题量** | 每个知识点至少 3 道独立题 | 低（已有现成数据集） | 高——直接解决「一次诊断耗尽题库」 |

**这份规划按 B 做，A 单独立项。** 理由在第三节。

### 验收标准（可量化）

| 指标 | 现状 | 目标 |
|---|---|---|
| 只有 2 题的知识点 | 364 | 0（或明确标注"补不到"的清单） |
| 每个知识点的独立题数 | 2–4，均 2.26 | ≥3 |
| 新题的溯源完整度 | — | 100%（source + source_id + 映射依据 + 置信度） |
| 未复核外部题进入诊断 | — | 0（默认关闭，显式开关才启用） |

## 二、缺口到底有多大（实测）

| 学段 | 知识点 | 2 题的点 | 3 题 | 4 题 | 候选池可用题 |
|---|---|---|---|---|---|
| 小学 | 203 | **180** | 23 | 0 | 10382 |
| 初中 | 127 | **87** | 30 | 10 | 2766 |
| 高中 | 147 | **97** | 50 | 0 | 6349 |
| 合计 | 477 | **364** | 103 | 10 | 19497 |

结论：**题量富余 50 倍**。要补的量是 364 道（每点 1 道）到 728 道（每点 2 道，留余量）。
不是"能不能找到题"的问题，是"能不能准确标到点上"的问题。

## 三、必须先承认的一件事：CMM-Math 不是「真题」

CMM-Math 的字段是 `id / question / options / answer / analysis / level / subject / image`。

- `level` 是**年级**（七年级、高二），不是年份
- **没有省份、没有试卷号、没有年份**
- `subject` 字段不可信（实测把解三角形题标成「解析几何」）

所以严格说，它是「中考/高考水平的题」，不是「2024 年浙江省中考第 17 题」。

真正带年份地区的源，我在上一轮已经查过：

| 源 | 规模 | 形态 | 拿到结构化题的代价 |
|---|---|---|---|
| 出卷网（chujuan.cn） | 高考数学 3027 套 | 网页 + MathML | 需爬虫 + 解析，且站点无知识点标签 |
| 21世纪教育网 | 2025 年 118 条 listing | Word/PDF/图片 | 需 OCR，版权归原出版方 |
| GaoKaoMath（HF） | 124 条，有 year/province | JSONL | 量太小，且题干英文 |

**判断：真题的地区/年份维度，对诊断引擎没有增量价值。**
引擎问的是"你会不会解一元二次方程"，不是"你会不会做 2024 年杭州卷第 17 题"。
把它做成"真题库"是另一个产品（刷题/模考），不是这个诊断器。

**所以本轮只接 CMM-Math，且导入时明确标注 `source: cmm-math`、不编造年份地区。**

## 四、数据怎么落：分文件，不混表

### 不建议的做法

直接追加进 `data/questions.json`。后果：

1. 「可机器验算 592（55%）」这个数字会失真——分母突然变成 3000，比率掉到 20%
2. 「复核覆盖 15%」同样失真——分母里混进几千道从没复核过的题
3. 「难度 basic 1042 / standard 35」会变成"basic 3000+"，而外部题**根本没有难度字段**
4. D19 那次「216 道答案键错了」是靠来源可追溯才查清的。混表后，出问题无法判断是自有题还是导入题

### 建议的做法

```
data/questions.json      自有题 1077 道，语义不变：经过作者复核和机器验算
data/questions_ext.json  外部题，字段同构 + 5 个溯源字段
```

外部题多出的字段：

| 字段 | 取值 | 用途 |
|---|---|---|
| `source` | `cmm-math` | 来源 |
| `source_id` | 原数据集 id | 可回溯到原始记录 |
| `source_license` | `BSD-3-Clause` | 合规 |
| `mapping` | `{method, confidence, evidence}` | 凭什么说这道题考这个点 |
| `usable_for_diagnosis` | `false` | 闸门，通过复核才翻 true |

`cnkg/graph.py` 的 `load_graph()` 增加 `include_external=False` 参数，**默认不加载**。
Web 端和模拟脚本显式开，报告里分别统计。

## 五、四道闸门：什么题才准进来

外部题进库前必须全过。任何一道不过，留在 `inbox/candidates/`，不进 `questions_ext.json`。

### G1 结构完整性（自动）
- 题干非空、无 `<ImageHere>` 残留
- 选择题：选项 ≥3、选项文本互不相同、答案字母在选项集合内
- 数值题：答案可解析、无歧义表述（不含"或""以上都对"）

### G2 答案可信（半自动）
- 数值题：**必须**能写出独立复算表达式 `verify`，否则不收
- 选择题：查答案字母分布（见第六节，小学池已发现异常）
- 全批抽样 30 道人工核答案

### G3 去重（自动）
- 与自有 1077 道：题干归一化后比对
- 与同批外部题：题干 + 选项集合双指纹
- 与已导入的外部题：同上

### G4 映射置信（自动 + 抽检）
见第六节。

## 六、映射方案：为什么不能只靠分类器

上一轮实测（`tools/topic_classify.py`，5 折、按知识点分组）：

| 设定 | top1 |
|---|---|
| 全库直接判章（117 类） | 27.6% |
| 只判是哪一册（23 类） | 35.8% |
| 已知册、判册内章 | 58.1% |

**58% 的意思是：每 2 道题就有 1 道标的章是错的。** 拿它自动落标，等于往诊断引擎里灌噪声。

### 采用方案：规则词表（高精度）+ 分类器交叉校验

每个知识点写一条判别规则，三组正则：

```json
"mh1.2.2": {
  "must": ["不等式|不等式组"],
  "any":  ["基本不等式", "\\\\sqrt\\{ab\\}", "a\\+b\\\\ge"],
  "not":  ["解集|数轴表示"]
}
```

- `must` 全中 → 限定题材
- `any` 至少中一项 → 限定考法
- `not` 一个都不能中 → 排除同名不同义

判定规则：
1. 只接受**唯一胜出**且领先第二名 ≥ 1.0 分
2. 若分类器给出的章与词表落标的章**冲突** → 不落标
3. 落标后写 `mapping.evidence`，记录命中了哪几条正则

### 预期收益（按高中估算）

高中 97 个 2 题点里，术语区分度高的（导数、数列、圆锥曲线、复数、概率分布、空间向量）
约 60–70 个能写出一条可靠规则。按每点补 1–2 道算，可补 80–130 道。
剩下靠分类器判不准的，进人工/模型队列，不硬塞。

## 七、一个之前没想清的问题：难度从哪来

引擎**真的在用 difficulty**（`cnkg/engine.py` 的 `DIFF_RANK`），用于选下一题和判断降档。
但 CMM-Math **没有难度字段**。

如果导入题标 `standard`，会怎样：
- 现有库里 1042 道 basic / 35 道 standard
- 导入 300 道 standard → 引擎会认为这个点"有 standard 题"，出题行为整体偏移

**处理方式（三层保护）**：
1. 导入题一律标 `difficulty: "basic"`，同时写 `difficulty_basis: "inherited_unverified"`
2. 引擎里让导入题**只作为第 3、第 4 题的候选**，不参与首次出题
3. 统计报告里把 `difficulty_basis` 分组展示，不与自有题混算

第 2 条是关键：即使难度标错，也不会影响诊断的第一次判断。

## 八、执行阶段与验收

### S1 · 映射实验（只出报告，不动数据）
- 产出：`data/kc_lexicon.json` + `build/question-bank/mapped_*.jsonl` + 精度报告
- 验收：随机抽 50 条已落标的题**人工逐条判**，精度 ≥90%
- 不达标的处理：**不进入 S2**，改为人工/模型逐题

### S2 · 高置信导入
- 过 G1–G4 的题写入 `data/questions_ext.json`
- 引擎默认不读，`usable_for_diagnosis` 全为 false
- 验收：364 个 2 题点里，被覆盖的比例 + 未覆盖清单（含原因）

### S3 · 复核与接入
- 每点抽 1 道复核（约 364 道），通过后 `usable_for_diagnosis = true`
- 引擎开关打开，重跑 `simulate.py` 与 `ladder_experiment.py`
- 验收：三档准确率不低于当前 71.9%，根因命中不低于 83.6%
  → **若下降，回滚到只读**（外部题仍可浏览，但不进诊断）

### S4 ·（可选，另立项）真题维度
只在需要"按年份地区筛题"这个功能时才做。

## 九、止损条件（提前定，避免中途改口）

| 条件 | 动作 |
|---|---|
| S1 抽样精度 <80% | 停止词表路线，改人工/模型 |
| S2 导入后被覆盖知识点 <30% | 承认词表覆盖不足，补规则或换方案 |

## 十一、需要拍板的三件事

1. **接受「CMM-Math 不是真题」吗？** 接受 → 走 S1–S3；不接受 → 先做真题源，成本高一个量级。
2. **外部题分文件还是混进 questions.json？** 我建议分文件，理由在第四节。

## 十二、S1 / S2 实际结果（2026-10-24 回填）

### S1 映射实验：验收未达标，方案按止损条款调整

| 项 | 结果 |
|---|---|
| 词表规则 | 144 条（覆盖高中 144/147 个知识点） |
| 可选池（单选、无多小问） | 3280 / 6349 |
| 规则自动落标 | 1310 道，覆盖 100 个点 |
| 抽样精度（第一轮，30 条） | **83.3%** |
| 抽样精度（第二轮，收紧规则+过滤后，30 条） | **约 83%** |

两轮都卡在 83%，说明这是**规则法的天花板**，不是某条规则没写对。
按第九节「S1 精度 <90% 不进入 S2」的条款，原方案应停。

**但不是放弃，而是换分工**：
规则继续负责**召回与排序**（它做这个够用，1310 道选了 68 个点各 1 条），
精度由**人对最终小集合逐条判断**保证。理由是我们只需要 97 道（高中），
这个量读得完；而追求规则法 90% 精度要无限调词，且每调一次都会打破别的规则。

### S2 导入：68 条候选 → 40 道入库

| 环节 | 数量 |
|---|---|
| 人工判定候选 | 68（覆盖 97 个缺口点中的 68 个） |
| 人工判为「归属正确」 | **45（66%）** |
| 机器结构检查再拦下 | 5（3 条选项 <3、1 条题干混解析、1 条答案不在选项内） |
| **实际入库** | **40 道，覆盖 40 个知识点** |

落盘 `data/questions_ext.json`，全部 `usable_for_diagnosis: false`。

**答案核验**：19 条解析里有「故选 X」且与答案字段一致；21 条无信号；
**0 条自相矛盾**。注意这只证明"解析和答案没打架"，不证明答案对——
所以仍然全部锁在诊断之外。

### 已知展示缺陷（未修）

40 道导入题里 **30 道含 LaTeX**（`$x^{2}$`、`\frac{1}{2}$`）、**4 道含 Markdown 表格**。
Web 端目前按纯文本渲染，这些题会显示成源码。

这不影响诊断（它们还没进诊断），但 S3 打开开关前必须解决，
否则学生看到 `$\frac{1}{2}$` 而不是 ½。可选方案：
引入轻量 KaTeX 渲染，或在导入时把公式降级成纯文本表述——后者会损失精度，不推荐。
