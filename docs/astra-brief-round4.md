## 二、最重要的一件事：答案现在是 option_id，不是字母

第三轮之后项目做了 M3.1 改造（选项身份稳定化）：

```
旧：choices = [{"key": "A", "text": "..."}, ...]   answer = "B"
新：choices = [{"id":  "o1", "text": "..."}, ...]   answer = "o2"
```

**字母现在是渲染时按顺序生成的，答案存的是 `o1`/`o2`/`o3`/`o4` 这样的稳定 id。**

这意味着：

1. `review.csv` 的 `options` 列里，`A．B．C．D．` 是**显示顺序**，不是身份。
2. `answer` 列写的是 id（如 `o2`），它对应 `options` 列里**第二个**选项。
3. 如果一道题的答案是错的，你要写的 `correct_option_ids=` 里也应该是 id，不是字母。

### 举例

某题 `options` = `A．30° | B．45° | C．60° | D．90°`，`answer` = `o3`。

- 正确答案是 C（60°），因为 o3 是第三个选项。
- 如果你认为答案错了，应该写：`correct_option_ids=o2, reason=...`
  （即正确答案其实是 B 45°）

**不要写 `correct_option_ids=C`。** 那样无法区分"指内容"还是"指位置"，
而这正是我们要消除的歧义。

## 四、review.csv（320 行）

抽样规则：短答题优先、standard 难度优先、每个根节点优先、每册轮转补齐。
题目顺序按 id 哈希排列，同一份输入永远得到同一份样本。

### 检查什么

1. **答案是否唯一正确**（选填）
2. **选项是否有歧义**（比如两个选项在特定条件下都成立）
3. **解析是否与答案自洽**
4. **题干是否缺少必要条件**（缺条件导致无法唯一确定答案）
5. **题干是否泄露答案**（括号里直接写出答案）
6. **公式/表格是否完整**

### 格式要求

- `verdict` 只能是 `pass` / `fail` / `skip`
- `verdict = fail` 时，`note` **必须以 `correct_option_ids=` 开头**
  （选择题写 id；非选择题写 `correct_option_ids=` 后接正确答案文本）
- `full_question_sha256` 是题目全字段指纹，**不要改**——改了说明题目内容被改了，
  我需要知道哪些题在回传过程中被改过
