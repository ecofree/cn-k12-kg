## 二、为什么要复核生成题

因为项目里加了 757 道**机器生成**的题，用来解决「题量不够导致公式定理记不住」的问题。

生成题有两种：

### A. 反向判断题（477 道）

题干形如「关于 X，下列说法正确的是」，四个选项里一个是**本知识点的正确表述**，
另外三个是**别的知识点的内容安到这个知识点上**（或者本知识点其它定理被改了条件）。

**这类题要重点看的是：干扰项是不是真的错？**

具体来说，请检查：
- 有没有哪个干扰项**其实也对**？（比如两个说法都能算作「关于这个知识点的正确说法」）
- 干扰项会不会**答非所问**到根本不是这个知识点、但学生看不出所以然？
- 正确项本身表述准确吗？

### B. 计算练习题（280 道）

形如「计算 23 × 45 = （  ）」，答案带 `verify` 表达式（机器已验算过算术）。

**这类题要重点看的是：题目问的到底是不是这个知识点的内容？**

`verify` 只能证明「算术是对的」，证明不了「这道题该归到这个知识点」。
比如「长方形的面积」和「正方形的面积」都用 `a*b`，算术都对，但归属不同。

## 三、格式要求（和第四轮一样）

- `verdict` 只能是 `pass` / `fail` / `skip`
- `verdict = fail` 时，`note` **必须以 `correct_option_ids=` 开头**
  （选择题写 option_id 如 `o2`；数值题写正确答案文本）
- **答案是 option_id 不是字母**：`options` 列里的 `A．B．C．D．` 是显示顺序，
  `answer` 列写的是 `o1`~`o4` 这样的稳定 id。`o2` 就是第二个选项。
- `full_question_sha256` 是题目全字段指纹，**不要改**。

---

## 四、特别提醒：生成题可能成片有问题

生成题是按模板产出的，**如果生成逻辑有系统性问题，会成片出错**，不是零星几个。

所以：
- 如果你在 `generated_review.csv` 里连续遇到 3 道以上同类问题（比如某类干扰项总是不对），
  **请在 note 里写清楚规律**，不要只标记单题 fail。
- 我已经用了自动检查挡住一部分（选项重复、答案位置偏斜、算术不一致），
  但「干扰项在数学上是否真的错」只能靠人看。

## 五、期望

- 生成题的整体 pass 率应该在 85% 以上。如果明显低于这个数，
  说明我的生成逻辑有系统性问题，我会整体重做而不是逐条改。
- 计算题（带 verify 的）如果 fail，多半是**知识点归属**问题而不是算术问题——
  请在 note 里写清楚它实际考的是什么。
- 如果发现某道题的**题干本身有歧义**（不是选项的问题），也请 fail，并在 note 里说明。
