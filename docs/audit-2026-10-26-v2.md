## 1. 结论

当前项目已经具备有价值的数学资料与补学工具基础：教材导航、原创讲解、练习、先修关系、实践项目、来源重建、版本快照与匿名学习记录均已存在。

离优质的完整学习产品，主要差距在于：课程能力粒度、任务与目标对齐、正确而公平的反馈、图形与操作表征、持续学习安排，以及统一的内容维护方式。继续扩充题目总数不会自动补齐这些差距。

上一轮“完成”指约定的制作清单与工程门禁完成，并不证明全课程的细技能已被穷尽。此次也发现了上一轮测试未覆盖的真实缺陷，应先修复，再做系统性升级。

推荐定位为“中国 1—12 年级数学的目标导向学习与补学系统”。当前仓库只覆盖数学；若把 K12 理解为全学科，语文、英语、科学等需要分别建立课程模型与内容，不宜在此阶段同时展开。

推荐保留现有资产，渐进迁移。Python、SQLite、原生前端仍可继续使用。优先改变领域模型与内容流程，不以更换技术框架作为质量提升指标。

## 3. 应先修复的真实问题

优先级含义：P0 为会直接给出错误数学反馈的问题；P1 为现有功能、契约或证据流程缺陷；P2 为有明确收益的产品与维护改进。

### A01 / P0：精确数值题使用统一浮点容差，错误答案会判对

位置：cnkg/verify.py 的 compare；web/server.py 的 judge。

当前判定为 abs(a-b) <= max(1e-6, abs(b)*1e-9)。to_number 先使用 Fraction，再转成 float，精确信息丢失。

| 题目 | 正确答案 | 提交 | 当前结果 |
|---|---|---|---|
| m8a.18.4-q101 | 0.0000006 | 0 | correct |
| 同题 | 0.0000006 | 0.0000001 | correct |
| m4a.1.2-q90 | 46961755349 | 46961755350 | correct |

这些题都在当前诊断池。大数题 q91/q92/q93 同样存在末位加一仍判对的问题。

改进：精确整数、有限小数、分数保持有理数精确比较；测量和近似计算逐题声明舍入与误差；要求最简分数、小数表示等形式时另查表达要求。不要只调整一个全局容差。

验收：正确答案、合法等价答案、数量级错误、末位错误、零、小数边界、分母为零、近似精度分别有真实题反例。

### A02 / P0：短答按字符串名单比较，合法数学表达被判错

位置：cnkg/verify.py 的 compare_short；web/server.py 的 judge；cnkg/learning.py 的 grade_task。

| 题目 | 系统参考答案 | 合法提交 | 当前结果 |
|---|---|---|---|
| m7b.9.1.1-q102 | (4,4) | (4.0,4.0) | wrong |
| m8a.17.1-q201 | 3xy(2x-3y) | 3yx(2x-3y) | wrong |

坐标题当前不能据一次错误判弱，但显示为错误仍会误导；因式分解题为练习用途，仍应给出公平反馈。

改进：逐步支持有理数、坐标、集合、区间、多项式等结构化答案类型；分别检查数学等价与任务要求的形式。复杂证明保持过程评价，不需要立即部署通用大模型判分。

### A03 / P0：边际成本解释把瞬时变化率说成有限增量

位置：tools/app_items/h4.py；题目 mh4.5.2.2-q101。

题目给 C(x)=x²+3x，导数 C′(2)=7，但解析把它解释为“再多生产一件增加的成本”。实际 C(3)-C(2)=18-10=8。

题目还没有明确产量单位，却把导数单位直接写为万元。应说明连续产量模型与产量单位；导数单位为万元/产量单位。有限增量用差分计算，导数乘小增量给出近似。

改进：修正题干、解释和作者源，同时增加“题义—单位—模型—计算”反例检查。verify 与作者提供的答案一致，只能证明该算式的计算一致。

### A04 / P1：CLI 诊断遇到选择题崩溃

位置：tools/query.py 的 _run_session，仍读取 choice['key']；实际题库采用稳定 choice['id']。

复现命令：python tools/query.py diagnose m1a.3.1 --answers c。

首道选择题“魔方是什么形状？”立即 KeyError: 'key'。Web 已完成选项 ID 改造，CLI 未同步。

改进：所有入口共用选项呈现和提交适配器。显示字母随排列生成，稳定 ID 用于答案与历史引用。将 README 承诺的 CLI 入口加入发布验收。

### A05 / P1：公开 Schema 与运行数据不兼容

位置：schema/topic.schema.json、schema/question.schema.json、tools/validate.py。

两个 Schema 禁止额外字段，但 477 个 topic 都有未声明的 exam_scope 等字段；3,568 个 question 都有未声明的 difficulty_basis 等字段。选择题 Schema 仍要求 choices[].key，实际 1,150 道选择题全用 id。

validate.py 使用另一套手写校验，不加载这些 Schema，因此“数据验证通过”和“公开契约有效”脱节。

改进：建立版本化的单一结构契约，供导入、构建、API、编辑工具共同使用；跨引用和数学业务规则继续用专门校验。补齐讲解、任务、项目、内容包和版本记录的契约。

### A06 / P1：材料例题与“新题检查”的曝光记录未统一

位置：web/server.py 的材料请求事件、_create_session、_present_question；data/teach/m6a.5.3.json 与 m5b.4.1.json。

已通过当前 Handler 和临时数据库实际复现：

| 教学材料 | 随后的检查第二题 |
|---|---|
| 圆面积例题：半径 3、π=3.14、面积 28.26 | m6a.5.3-q2，同半径、同答案 |
| 正方体自检：棱长 3、表面积 54、体积 27 | m5b.4.1-q2，同棱长求表面积 54 |

教学卡访问有 material_requested 标记，却没有关联到题目/题族。后续 repeated_question_ids 为空，因为只查历史答题会话里的 presentations。

边界：系统仍保持 independent_evidence=false，不能指控它把这些记录直接标为独立掌握。教学材料被请求也不等于答案已被展开。

改进：例题、自检、练习和检查共享 item_family_id。区分材料已提供、参考已展开、独立尝试、反馈已提供四类事件。检查选用未曝光的题族或明确不同的表现任务。

### A07 / P1：题池耗尽后仍提供“新题复测”入口

位置：web/server.py:649–687；cnkg/engine.py 的选题；web/static/app.js 的检查按钮。

正式检查永久排除本浏览器过去呈现的题。m1a.3.3 的两道检查题做过后，下一轮零题结束，状态为 untested、insufficient_items；静态按钮仍显示可以新题复测。

改进：区分未见检查、不同题族迁移、允许重复的间隔复习。服务端返回剩余可用题量；新题不足时明确转到复习，不重置曝光记录伪造新证据。

### A08 / P1：外部题跨来源互证会误并数学上不同的题

位置：cnkg/evidence.py 的 norm_stem、grade；tools/grade_ext.py 的 cross_source_hashes。

norm_stem 删除数学符号，导致“请计算算式2+3的值。”和“请计算算式2-3的值。”同 hash。互证只看来源字符串不同，没有核对答案与选项。

本轮用来源 A/答案 5 与来源 B/答案 -1 的两条合成输入，均得到 corroborated，并备注“跨源同题且答案一致”。输入及结果保存在 evidence.json。

边界：这是外部导入路径缺陷，不表示当前 own-only 发布题库已经被这组数据污染。

改进：保留数学语义的规范化；比较题干、条件、选项与答案；记录来源谱系，同源转载不算独立互证；矛盾进入隔离。修复后再扩外部导入。

### A09 / P1：没有检索到考试题，被自动解释成“不单独考查”

位置：tools/set_exam_scope.py、tools/check_stage_policy.py、data/topics.json。

工具把 0 命中设为 textbook_only；题池不存在时也会走入此分支。当前分布为 examined 409、textbook_only 62、source_gap 6。

缺检索结果不能证明不考。应拆为 source_observation=found/not_found_in_scanned_sources/source_unavailable；只有明确考试范围依据才能填 exam_scope，否则 unknown。删除“未检出即不考”的自动推断，保留课程知识。

## 4. 课程设计上的主要差距

### 4.1 教材位置与能力混为一体

当前主键包含册次、章、节；目标以字符串数组加 criterion_index 绑定。它适合教材导航，但不适合跨教材版本、跨年级、跨表征维护同一种能力。目标重排也会改变下标。

所有节点都恰有两个目标，不足以说明每个目标可独立测量。例如“能计算长方体与正方体的表面积和体积”同时包含形体区分、表面积/体积、不同公式、单位、封闭/无盖条件和建模。一个棱长 3 的正方体任务不能覆盖所有表现。

改进应由可观察行为决定技能粒度，不预定每章必须 2、5 或 10 个目标。

### 4.2 核心/工具分类适合组织，不应豁免起始教学

一年级 38/53、二年级 32/40、三年级 31/45 个节点被归 tool。小学工具点练习数量门槛为 1。其中有数的认识、分与合、乘法意义、分数认识、面积单位等基础概念。

“盘子里有 3 个苹果，用数字表示是几？”可测轻量数字识别，不能测出学生是否能逐个点数、避免漏数重数或书写数字。

如果项目定位为已有基础者的补学速查，可以保留简短材料；如果要支持从零学习，应增加可选的起始教学。可将基础解释默认折叠，并允许入口任务通过者跳过，避免给熟练学生增加负担。

### 4.3 材料已有，连续学习流程尚未覆盖大部分内容

684 个核心自检是临时文本框，切换页面前需自行复制；34 个单元过程任务可保存作答，但只停留在 needs_review；18 个项目主要显示步骤和量规，没有统一的作品、反思与完成记录。

无需等待教师独立审核，可以先保存草稿、步骤、学生自评、作品说明和反思，标明证据来自学生自查；它们不自动产生独立掌握结论。

学习历史已经支持恢复和导出，应复用。新增的是按技能整理的待巩固、错因线索、到期复习和下一步任务。

### 4.4 图形、操作与多表征需要系统补强

应优先制作能服务具体目标的数轴、十框、分数模型、几何图、坐标图、表格与数据图；图形也应有替代描述、键盘操作和打印方案。没有必要为每道题添加装饰图片。

IES 的学习指导建议把图示与语言、具体与抽象表示相连，并将例题与独立解决问题交替安排。EEF 的数学指导同样强调表征要有明确教学目的、处理误概念、建立概念与程序的联系。这里将这些研究方向转化为产品设计建议，不据此宣称本项目已经证明有效。

### 4.5 需要真正的任务家族与认知要求标签

相似三角形 m9b.31.2.3-q102 和 q201 都是相似比 2:3、小三角形面积 12、求大三角形面积 27，却分别标 advanced、standard。数学归纳法 mh4.4.4-q102 标 advanced，实际只问 n 从 9 到 10 增加哪一项。

新增 family_id/variant_id，独立任务覆盖按题族与表征统计。把预设认知要求（直接执行、解释、多步策略、证明/建模）和经验难度分开；后者按用户要求暂不校准。

684 个核心自检中，86 个与同主题题库题干相同；这些对应题均为练习用途，不在诊断池。合理复用可以保留，不能为了去重而删掉必要练习；只要避免将它们充当未见迁移证据。

### 6.2 学习流程

学生选择年级、教材或具体目标后，看到继续上次、今天建议与按教材查找。先确定一个可完成的目标，再按需要进入起始解释、带提示练习、独立任务、错误辨析、迁移和后续复习。

一个以分数加法为例的新单元可以这样设计：

1. 入口判断学生能否辨认同一整体与等分单位，结果只决定学习起点。
2. 用同长线段或同面积矩形展示不同分母所表示的单位。
3. 完整示范一次通分，再提供缺少关键步骤的例题，由学生补全理由。
4. 独立完成计算并解释为什么分母不能直接相加。
5. 比较正确解法与典型错误，学生选择或说明自己的思路，形成待确认错因线索。
6. 用不同表征或真实情境迁移，例如原长不同的两卷绳子，要求判断信息是否足够。
7. 记录参考答案是否展开、提示次数、过程与自评；下一次回访展示到期复习。

复习间隔应可配置并保留实际时间，不把固定间隔视为已经验证的最优方案。界面报告“在哪类任务上展示了什么”，避免以一次作答给整章贴永久掌握标签。

### 6.3 技术实现

保持单体应用，按职责分成内容查询、评分、会话、曝光与计划模块。SQLite 仍适合当前本地规模。

局部改善包括：历史摘要分页、曝光索引、按技能查询；将会话绑定到所引用资源的不可变版本。当前 graph_version 绑定全库，修改无关高中新题也会阻断小学生未完成会话；保留旧版本完成原会话会更合理。

公开部署是独立阶段：届时补 HTTPS、服务边界、记录删除、恢复与备份。当前本地使用不需要立即建设多租户学校平台或复杂账号体系。

## 8. 作者与发布流程如何优化

当前已有 23 册显式真源与重建门禁，应保留。剩余问题是教学正文分散在 JSON、app_items、teach_*、complete_* 等 Python 脚本中；tools 下有 140 个 Python 文件，迁移、实验与正式构建入口混杂。

建议采用以下统一流程：

1. 定义可观察技能及其条件。
2. 先设计任务蓝图：讲解目标、误概念、表征、评分和用途。
3. 内容作者编辑单一 JSON/Markdown 来源；Python 只处理编译、引用、参数化和检查。
4. 一次编译生成 API 内容包、搜索索引、数据库、覆盖报告与变更影响清单。
5. 检查结构、引用、数学反例、单位、同题家族、曝光与评分契约。
6. 预览实际网页与移动端，执行关键用户旅程及 CLI。
7. 输出版本化发布包及素材/依赖清单。

历史补全脚本冻结为迁移工具。每一类资源只能有一个可编辑的作者源，避免修改输出后被旧生成器覆盖。

验收要关注用户行为而非测试数量：保留“学习→提交→刷新继续”“检查→反馈→下一步”“历史恢复/导出与手机输入”三条浏览器旅程。上轮浏览器脚本只保存在临时目录，应进入仓库并可在 CI 重复执行。

移动端适配之后，应按 WCAG 2.2 检查键盘焦点、控件大小、替代文本、输入说明与错误提示。现有 aria 标签和按钮语义应保留；本轮没有做完整无障碍合规测试。

README 已声明代码 MIT、原创资料 CC BY 4.0，但未找到独立 LICENSE/NOTICE 文件；随包前端依赖与字体也应列出版本、来源和对应许可文本。这里建议完善发布资料，不作额外法律结论。

## 10. 推荐三批实施与验收

### 第一批：恢复正确反馈与一致契约

范围：A01—A05；修正外部互证和 exam_scope 推断；覆盖 README 声明的入口；整理重复副本与有效文档入口。

验收：

- 小数、分数、大整数与结构化合法变体正确判定；错误反例被拒绝。
- Web、CLI、单元任务共用评分协议；CLI 能完成选择题流程。
- 正式数据符合真实生效的版本化 Schema。
- 边际成本题义、单位与解释修正并进入反例回归。
- 不同数学题不能因符号被删除而互证；题源缺失不会变成不考。

这一批不以增加新题为目标。

### 第二批：打通一条完整的能力学习链

范围：稳定 Skill、统一 Task/AnswerSpec、题族与曝光、持久化自检、学习计划。选择已有资源较多的“分数→比与比例→一次函数”链做完整迁移。

验收：

- 链上每个目标有可观察表现、适用任务和评分依据。
- 同一目标可以映射多个教材位置；旧 ID 和历史记录仍能访问。
- 例题答案曝光与检查选题统一处理；无新题时给出真实可执行的下一步。
- 自检与过程草稿可恢复，学生自评保持独立身份标记。
- 下次打开能看到继续学习与到期复习，记录真实间隔。
- 新增无关材料不阻断原会话按旧版本完成。

### 第三批：扩大课程深度并收敛维护成本

范围：按领域迁移其余材料，补图形/操作/证明/建模、低年级可选起始教学、作品档案与适龄入口；建立全资源单一作者源与发布包。

验收：

- 公布可解释的技能清单与覆盖分母，不再用教材点数替代全课程细技能。
- 各目标按适用项拥有解释、练习、独立任务、迁移和复习；不适用项注明理由。
- 同题复制不增加独立覆盖；需要图形或过程的目标有对应任务。
- 所有学习材料的提交/作品/参考展开都按统一协议记录。
- 一个命令重建全部正式资源，重复构建一致；关键浏览器旅程可重复验收。
- 旧脚本、旧文档、研究数据与正式发行包边界清晰。

教师独立审核与真实学生效果验证继续保留为暂缓状态，不作为上述三批完成的阻塞项。
