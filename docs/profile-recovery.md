# 学习档案恢复与迁移

学习记录属于本地学习服务中的档案。浏览器凭据用于找到它；课程内容数据库和学习数据库分别保存。以下流程已经接入“档案与恢复”页面，入口为 `/?profile=1`。

## 先准备恢复方式

1. 在仍能看到原学习记录的浏览器打开“档案与恢复”，填写档案名称，选择“创建恢复码”。
2. 保存这次显示的恢复码，可复制或下载文本。之后不会再次显示原码；恢复码与备份文件分别保存。
3. 选择“下载加密备份”。后续继续学习后，再下载新的备份，以便恢复到最近的保存时点。

备份保存会话原始作答、冻结题面和 SVG、作品及全部修订、未解决事项的来源和暂缓记录、提示与曝光事件、请求去重信息。它使用恢复码加密，不包含独立教师审核或学生效果验证结论。

## 按场景恢复

| 情况 | 所需材料 | 操作与结果 |
| --- | --- | --- |
| 换浏览器、清理站点数据，但原学习服务和学习库还在 | 恢复码 | 打开同一学习服务的“档案与恢复”，输入已有恢复码，选择“凭恢复码找回”。此前浏览器的登录凭据失效，需按同样方式恢复。 |
| 换电脑、学习服务重装或原学习库已不在 | 加密备份及制作该备份时的恢复码 | 安装项目并启动服务，打开恢复页，选择完整备份文件，输入对应恢复码，选择“导入备份并恢复”。恢复到备份时点。 |
| 更换恢复码后需要使用旧备份 | 旧备份及旧码 | 旧备份仍由制作时的码解密；新码用于当前服务及新备份。更换后请重新下载备份。 |
| 仅需阅读或核查记录 | 可读学习记录导出 | 在历史页导出；此文件用于查阅，不能作为可恢复备份导入。 |

导入不会合并或覆盖已有同名资源。资源身份冲突、错误恢复码、损坏密文或不兼容版本会使整个导入回滚，已有记录不改变。完整备份导入目前接收 schema 4；旧运行数据库由项目迁移代码升级，不能把其他版本的可读导出重命名成备份。

若浏览器凭据、恢复码与学习库/备份全部丢失，系统不能凭档案名称重新生成学习记录。未创建恢复方式前不要把浏览器清理当作一种迁移方法。

## 内容变更和旧问题

恢复保留原任务身份、内容版本和原始评分，不使用当前答案批量重判旧作答。备份中的暂缓记录会继续显示在“待解决事项”。原版本的支持活动可以按冻结内容继续；若评分程序发生不兼容改变，页面保留旧内容和已作答部分，并说明续做限制。

档案恢复与自动学习结论分开。使用恢复码只恢复访问；提示后答对只提供有帮助的后续观察，自评仍是学习者报告。它们都不能直接变成独立掌握证据。

## 维护者说明

运行依赖由 `requirements.txt` 固定，其中 `cryptography` 提供 AES-GCM。恢复凭据和浏览器别名只存散列，JSON响应不返回档案内部所有者ID或浏览器凭据；会话Cookie为 HttpOnly。轮换恢复码或找回档案会撤销旧浏览器别名。

原始学习库默认 `var/learning.sqlite`，可由 `CNKG_LEARNING_DB` 指定；发布内容库为可重建的 `build/kg.sqlite`。前者及用户备份不进入源码与发行证据包。自动恢复测试使用临时数据库和合成作品；证据包只保留允许的测试报告和截图。

本地档案恢复不提供学校账号、多人同时登录策略、云同步或公网身份服务；这些不是当前本地项目的运行前提。
