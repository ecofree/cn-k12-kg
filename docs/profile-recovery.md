# 学习档案恢复与迁移

学习记录属于本地学习服务中的档案。浏览器凭据用于找到它；课程内容数据库和学习数据库分别保存。以下流程已经接入“档案与恢复”页面，入口为 `/?profile=1`。

## 先准备恢复方式

1. 在仍能看到原学习记录的浏览器打开“档案与恢复”，填写档案名称，选择“创建恢复码”。
2. 保存这次显示的恢复码，可复制或下载文本。之后不会再次显示原码；恢复码与备份文件分别保存。
3. 选择“下载加密备份”，确认浏览器实际把文件保存到了哪里。页面显示“已生成并请求浏览器保存”，不会把服务端生成成功当作文件已经落盘。
4. 在“核验已保存的文件”中选择下载目录里的实际文件，填写制作这份备份时的恢复码，再选择“核验文件，不导入”。核验不切换档案，也不导入或重写学习记录。
5. 后续继续学习后，根据“当前记录与备份是否一致”提示生成并核验新备份。文件和对应恢复码要继续保留。

备份保存会话原始作答、冻结题面和 SVG、作品及全部修订、未解决事项的来源和暂缓记录、提示与曝光事件、请求去重信息。它使用恢复码加密，不包含独立教师审核或学生效果验证结论。

## 读懂备份状态

| 页面状态 | 已经确认的事实 | 下一步 |
| --- | --- | --- |
| 最近生成备份 | 服务已成功构造并加密完整快照；未证明浏览器实际保存了文件 | 确认下载位置，选择实际文件核验 |
| 最近选取文件核验，与当前记录一致 | 所选文件可用提供的恢复码解密，内部记录关联有效，其六类学习资产与当前保存记录一致 | 保存文件和对应恢复码；继续学习后更新 |
| 文件与当前记录已有差异 | 生成或核验之后，会话、作品、修订、保存重试、活动或接触记录中至少一类改变 | 生成并核验新备份；旧文件仍可用于其保存时点 |
| 文件使用旧恢复码 | 文件可解密，但该档案已更换服务端恢复码 | 保留旧文件对应的旧码，同时用新码制作新备份 |
| 曾生成过备份，但没有完整对比信息 | 旧版本只保存了生成时间，没有可比较的内容摘要 | 重新生成并核验，不能凭时间推断没有遗漏 |
| 最近导入的备份时点 | 已在当前安装实际完成导入 | 可查看历史和修订；查看材料产生的新接触记录也会触发更新提示 |

新鲜度比较包含六张资产表的全部记录，不以秒级或毫秒级时间相等代替内容相等。仅更新一条作品、一次接触次数或保存重试记录，也会被发现。跨安装导入时，本地事件序号及其接触索引引用按本档案顺序比较；数据库序号重排不会把完全相同的学习资产误报为新增学习。

文件核验确认的是所选文件**此刻**可解密、内部结构和关联可读取，以及它保存的记录版本。它不证明文件将来仍未丢失、不等于已在另一安装成功恢复，也不确认任何学习目标已经掌握。选择另一档案的文件核验，只显示该文件的核验结果，不会切换当前档案或覆盖当前档案的核验回执。

## 按场景恢复

| 情况 | 所需材料 | 操作与结果 |
| --- | --- | --- |
| 换浏览器、清理站点数据，但原学习服务和学习库还在 | 恢复码 | 打开同一学习服务的“档案与恢复”，输入已有恢复码，选择“凭恢复码找回”。此前浏览器的登录凭据失效，需按同样方式恢复。 |
| 换电脑、学习服务重装或原学习库已不在 | 加密备份及制作该备份时的恢复码 | 安装项目并启动服务，打开恢复页，选择完整备份文件，输入对应恢复码，选择“导入备份并恢复”。恢复到备份时点。 |
| 更换恢复码后需要使用旧备份 | 旧备份及旧码 | 旧备份仍由制作时的码解密；新码用于当前服务及新备份。更换后请重新下载备份。 |
| 仅需阅读或核查记录 | 可读学习记录导出 | 在历史页导出；此文件用于查阅，不能作为可恢复备份导入。 |

导入不会合并或覆盖已有同名资源。资源身份冲突、错误恢复码、损坏密文或不兼容版本会使整个导入回滚，已有记录不改变。当前支持加密备份版本 1、备份内容版本 1、学习记录 schema 4；此前同格式的备份继续可用。旧运行数据库由项目迁移代码升级，不能把其他版本的可读导出重命名成备份。

遇到未识别的备份或学习记录版本，应保留原文件和制作时的恢复码，使用生成备份时的项目版本，或明确声明支持该备份版本的后续程序。不要手工改版本号绕过检查。恢复页的“容量与兼容范围”直接显示当前程序接受的版本；失败的核验和导入不会更换浏览器凭据或清理旧记录。

若浏览器凭据、恢复码与学习库/备份全部丢失，系统不能凭档案名称重新生成学习记录。未创建恢复方式前不要把浏览器清理当作一种迁移方法。

## 内容变更和旧问题

恢复保留原任务身份、内容版本和原始评分，不使用当前答案批量重判旧作答。备份中的暂缓记录会继续显示在“待解决事项”。原版本的支持活动可以按冻结内容继续；若评分程序发生不兼容改变，页面保留旧内容和已作答部分，并说明续做限制。

档案恢复与自动学习结论分开。使用恢复码只恢复访问；提示后答对只提供有帮助的后续观察，自评仍是学习者报告。它们都不能直接变成独立掌握证据。

## 维护者说明

运行依赖由 `requirements.txt` 固定，其中 `cryptography` 提供 AES-GCM。恢复凭据和浏览器别名只存散列，JSON响应不返回档案内部所有者ID或浏览器凭据；会话Cookie为 HttpOnly。轮换恢复码或找回档案会撤销旧浏览器别名。

原始学习库默认 `var/learning.sqlite`，可由 `CNKG_LEARNING_DB` 指定；发布内容库为可重建的 `build/kg.sqlite`。前者及用户备份不进入源码与发行证据包。自动恢复测试使用临时数据库和合成作品；证据包只保留允许的测试报告和截图。

### 容量与完整安装快照

单档案便携备份目前限制为 50 MiB 解密内容、70 MiB 加密文件，以及每类资产表最多 100,000 行。恢复页显示按完整数据计算的容量；达到任一上限的 80% 会提示提前准备，超限会明确拒绝生成或导入，**不会只取最近记录来伪装完整备份**。服务端的生成时间和成功回执也不会因失败而更新。

长期积累的大档案或整套本地安装，可以由有权维护这份学习库的人使用 SQLite 的备份接口保存完整数据库快照。这个操作包含该安装的全部档案，文件没有应用层加密，因此应放在本机私有目录、加密存储或受控备份介质；不要放进项目仓库、公开发行包或共享内容目录。普通学习者的网页接口不会导出其他人的档案。

先暂停新的学习操作，在项目根目录、使用项目 Python 环境运行下面的命令。它只读打开当前学习库，创建一个新的私有快照文件，不覆盖既有备份：

```bash
python - <<'PY'
from datetime import datetime, timezone
import os
from pathlib import Path
import sqlite3

source = Path(os.environ.get("CNKG_LEARNING_DB", "var/learning.sqlite")).resolve(strict=True)
private_dir = Path.home() / "cnkg-private-backups"
private_dir.mkdir(mode=0o700, parents=True, exist_ok=True)
name = datetime.now(timezone.utc).strftime("learning-%Y%m%dT%H%M%S%fZ.sqlite")
destination = private_dir / name
fd = os.open(destination, os.O_CREAT | os.O_EXCL | os.O_WRONLY, 0o600)
os.close(fd)
with sqlite3.connect(source.as_uri() + "?mode=ro", uri=True) as original:
    required = {"sessions", "events", "works", "work_revisions", "work_requests", "exposures"}
    tables = {row[0] for row in original.execute("SELECT name FROM sqlite_schema WHERE type='table'")}
    if not required <= tables:
        raise RuntimeError("来源不是完整学习库；不要用可重建的内容库替代学习备份")
    with sqlite3.connect(destination) as snapshot:
        original.backup(snapshot)
        if snapshot.execute("PRAGMA integrity_check").fetchall() != [("ok",)]:
            raise RuntimeError("快照完整性检查未通过；保留原学习库，不能用这份快照替换它")
print("已建立完整数据库快照：", destination)
PY
```

保留这个文件及匹配的项目提交或发行包。在另一安装中复制一份快照作为工作库，保留最初快照不再改写，再使用它启动匹配版本的服务，例如：

```bash
CNKG_LEARNING_DB="/你的私有目录/恢复验证副本.sqlite" python web/server.py --port 8766
```

在新浏览器打开 `http://127.0.0.1:8766/?profile=1`，用原恢复码找回档案。核对作品数、修订、原题面和图示、未解决事项，再试保存一份新修订。验证成功前继续保留原学习库和原快照。完整安装快照不会通过网页“导入备份”按钮上传；那个按钮只接受单档案加密格式。两条恢复路径分别保留自己的实际验证记录，不混称为同一种备份。

本轮新增的 `profile_backup_receipts` 只记录生成、文件核验、导入的操作元数据，不参与六类学习资产摘要，也不把核验行为改写成学习记录。文件核验端点为 `POST /api/profile/verify-backup`，使用当前浏览器的真实档案身份做比较，忽略客户端自称的所有者或“已保存”标记。

本地档案恢复不提供学校账号、多人同时登录策略、云同步或公网身份服务；这些不是当前本地项目的运行前提。
