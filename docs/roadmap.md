# 当前质量范围与维护规则（Quality V7）

本轮继续处理 V6 留下的任务元数据、有限观察目标、错误分支和学习连续性缺口，保留 23 册、477 个导航点及原 1,136 个目标身份，新增 642 个有限可观察目标。作者源、登记、目录及全目标／全活跃题对齐已重建，范围检查的不完整目标数为 0。实现与具体证据见 [V7 续作记录](quality-v7-continuation.md)；历史 V5／V6 台账保留原样。正式验收状态以当前干净提交绑定的完整报告为准。

多客观题族统计已合并经审查的等价名称；66 项实践目标按作品量规单独观察。V6 的 400／1,070 变为本轮 412／1,712，主要背景是追加 642 个有限目标，多数本来只有单一结构。达到条件的目标增加 12，不足数随分母扩大增加 630；不能将这个变化包装成教学退步或广度问题已经解决。即使登记两种结构，仍须考虑实际帮助、参考、历史曝光及重复，才能讨论具体后续观察；登记数量本身不证明学生迁移、掌握或长期保持。

原 77 项未具有实际错误分支的单元支持现已全部补齐。维护重点转为检查每条路线是否仍匹配目标和确认任务、每层提示是否只归因实际方法，以及草稿和历史版本能否恢复。一次错误选择只支持可能假设，不能给学生固定能力标签。[支持完成审查](reviews/v7-instructional-support-completion-ai-review.json)

## 用户已明确暂缓的两项

- 教师独立审核保持待审核；AI 作者与 AI 交叉核对不能代签教师身份。
- 真实学生教学效果验证不虚构参与者、对照组、学习增益、长期保持率或难度校准。

两项未被计作完成，也不阻断已经授权的工程与材料维护。真实验证开始时另行确定范围、记录方式与判断依据。

## 持续维护顺序

内容修订按“目标及条件 → 任务与量规 → 解释与表征 → 作者 JSON → 编译及差异检查 → 具体语义复核 → 实际页面预览 → 固定版本验收”的顺序进行。题面改变必须同时核对答案、旧 `accept`、唯一有效评分合同、题族与任务用途；单独通过 `verify` 或作者答案自判不足以接纳变化。

有限目标必须说明观察行为和条件。已给模型的计算不能冒充自主建模，输入数值不能冒充作图、口头表达或证明；相关支持关系也不自动构成 `refines` 或先修蕴含。原目标、位置和 ID 保留，新增解释、辨别、提示及标准必须读实际任务逐项写出。[目标登记依据](reviews/v7-observable-goal-review.json)

不进位与进位、恢复原量与继续当前量等结构区别需有明确判断。已声明族的等价改名使用 `data/task_family_aliases.json`；历史未知族只使用 `data/task_family_history.json` 中经逐题审查的负向曝光关系。合同改变时须判定结构是否仍相同，不能仅凭同 ID 自动认同。原分类、答案、选项身份、曝光与作品历史不批量重写，也不能清零旧接触把改名后的方法包装成未见证据。

新版提示只归因实际展开的方法，不能用未选路线或后续内容扩大曝光。主族与辅助族都按实际提供时机记录。帮助后完成、学生自评和过程修订可以改变后续安排，不能直接变成独立掌握；缺少适合的后续任务时保留待观察事项。

新诊断不为未作答先修生成 `assumed`，历史推断保留并标为未实测。计划检查实际观察了哪个目标，保留其他目标的先修入口；没有错误记录的未完成指导也能继续。推荐优先覆盖不同候选题族，数量变式不能挤占其他方法。[运行审查](reviews/v7-runtime-continuation-review.json)

新答案、图示、提示和量规产生新内容版本。先保存独立原作答再展示帮助，保存失败或冲突保留输入；相同提交重试返回已保存结果，不重复计分或造事件。旧作品继续使用原快照，缺少字段如实说明；缺摘要不能调用当前引擎补判，缺当前任务的旧活动保持未完成阻塞。未解决事项跨会话、阶段、学段和版本保留。

概率统计、方程反例和数值正文按专项记录维护；故意错误示例须绑定具体位置、完整语境和指纹，不能用关键词全局跳过。程序精确核算的范围与模型条件、一般证明、数学语义分别说明。[统计任务数学审查](reviews/v7-statistics-task-mathematics-review.json) · [数值正文续审](reviews/v7-numeric-prose-continuation-review.json)

教材、课标条款、授权来源及发布依赖继续维护。学校账号、云同步、多租户和公网部署属于可选扩展；完整无障碍符合性也需要另有范围的审核，不能由窄屏与键盘定向检查替代。

新增或修改发行文件后重新生成发布清单并提交，在干净提交上运行全套门禁。失败、遗漏或旧指纹报告不用于打包；专项测试不替代最终集成报告。具体步骤见 [发布流程](release-workflow.md)，运行与资产交接见 [handoff](handoff.md)。
