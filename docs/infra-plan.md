## 二、CMM-Math 值不值：四条实测

### 1. 覆盖率（最硬的一条）

| 学段 | 缺口知识点 | 规则能召回到候选的 | 人工判定后真正入库的 |
|---|---|---|---|
| 高中 | 97 | 68（70%） | **40（41%）** |
| 初中 | 87 | 待测（缺词表） | — |
| 小学 | 180 | 待测（缺词表） | — |

高中是术语最清晰的学段，覆盖率也只有 41%。初中和小学只会更低，不会更高。

### 2. 独特性：不重复

40 道入库题与自有 1077 道的**题干完全重复数为 0**。这说明它带来的是真正的增量，
而不是把我们自己写过的题换个说法再放一遍。

### 3. 质量缺陷（全池统计，不是抽样）

| 缺陷 | 小学 | 初中 | 高中 |
|---|---|---|---|
| 明显错字（粗圆/圆雉/己知） | 0.5% | 0.7% | **1.4%**（粗圆 54 处） |
| LaTeX 破损（`$` 或花括号不成对） | 2.0% | **4.6%** | **4.4%** |
| 含 Markdown 表格 | — | — | 4/40 入库题 |

两类缺陷都是**机械可修**的：错字有固定映射表，LaTeX 破损可以按规则补齐或直接拒收。
但不能不修——4.4% 的破损率意味着每 23 道就有 1 道渲染成乱码。

### 4. 结构性缺项

- **没有难度字段** → 只能继承标记，不能参与难度判断
- **没有年份/地区** → 做不了真题维度
- **`subject` 字段不可信**（解三角形被标"解析几何"）→ 完全不用
- **28% 依赖配图** → 已整条排除，等于可用量再打七折

### 结论

**值得用，但必须配一层清理。** 定位是「补题量的原料」，不是「开箱即用的题库」。
按现在的效率（68 候选 → 40 入库），高中 97 个缺口点最多能补到 40–50 个，
剩下的一半要靠自己写或换源。

## 三、数学公式：怎么解决，装什么

### 现状

40 道入库题里 **30 道含 LaTeX**（`$x^{2}$`、`$\frac{1}{2}$`），4 道含 Markdown 表格。
Web 端现在按纯文本渲染，学生会看到源码。

### 三个方案对比

| 方案 | 体积 | 离线 | 公式质量 | 集成成本 | 判断 |
|---|---|---|---|---|---|
| **KaTeX**（本地静态文件） | 275 KB JS + 60 KB CSS + 字体约 1 MB | ✅ | 高，覆盖中学全部符号 | 低：一个 `<link>` + 一个 `<script>` + 遍历文本节点 | **采用** |
| MathJax | 1 MB+ | ✅ | 更高（支持更多宏包） | 中 | 过重，中学用不到 |
| 服务端预渲染 SVG | 需 Node 依赖 | ✅ | 同 KaTeX | 高：构建期产物，改题要重跑 | 不必要 |

### 决定：KaTeX 本地化

不需要 pip、不需要 Node 运行时。**只是把静态文件放进 `web/static/vendor/katex/`**，
浏览器直接加载，完全离线。

要处理的四种情况：

1. `$...$` 行内公式 —— KaTeX 自动渲染
2. `$$...$$` 独立公式
3. **裸 LaTeX**（`\frac{1}{2}` 没有 `$` 包裹）—— CMM 数据里存在，需要兜底正则
4. **Markdown 表格**（`| 每年体检 | ... |`）—— KaTeX 管不了，单独写个极简表格渲染

## 四、要不要 OCR

### 本轮：不要

因为已经定了「先补题量、不追真题」。CMM-Math 是结构化 JSON，**不经过 OCR**。
现在装 OCR 等于为一个当前不做的目标提前付成本。

### 什么时候会需要

只有当我们真的要「2024 年浙江省中考卷第 17 题」这种带年份地区的真题时才需要。
而那时面对的 PDF 有两个特点：

- 21世纪教育网的真题**大量是图片版/扫描版**（页面标题直接写「图片版」「扫描版」）
- 公式密集，通用 OCR 会把 `x²` 认成 `x2`、把分数认成两行

### 如果要做，四个选项

| 方案 | 公式能力 | 成本 | 部署 |
|---|---|---|---|
| Mathpix API | 最强，直接出 LaTeX | 按页计费 | 云，需 key |
| pix2tex（LaTeX-OCR） | 强，专攻公式 | 免费 | 本地，需 PyTorch 约 2 GB |
| PaddleOCR | 中文强，公式弱 | 免费 | 本地，约 500 MB |
| 腾讯云/百度通用 OCR | 公式基本不行 | 按次计费 | 云 |

**判断：真要做真题，公式部分必须用 Mathpix 或 pix2tex，通用 OCR 出来的题没法用。**
这台机器有 12 GB 显存，跑 pix2tex 可行，但先不装。

## 五、执行顺序

| 步骤 | 做什么 | 验收 |
|---|---|---|
| **S2.1** | KaTeX 本地化 + 公式/表格渲染 | 打开 Web 端一道含 `\frac` 的题，看到的是分数而不是源码 |
| **S2.2** | 数据清理层：错字映射表 + LaTeX 破损检测与修复 | 全池重跑，破损率降到 <0.5%，修不了的直接拒收 |
| **S2.3** | 初中词表（87 个缺口点）+ 候选 + 人工判定 | 同高中流程 |
| **S2.4** | 小学：先查答案分布异常（D 只占 8%），再决定要不要用 | 查清原因才动 |
| S3 | 抽样复核 + 打开诊断开关 | 模拟指标不下降 |

**先做 S2.1 和 S2.2**，因为它们的产出会被后面所有步骤复用；
初中和小学的补题如果渲染不了公式，补了也白补。

## 六、执行结果（2026-10-24 回填）

### S2.1 公式渲染：已完成

| 项 | 结果 |
|---|---|
| 方案 | KaTeX 0.16.11 本地化，`web/static/vendor/katex/` 共 1.5 MB（JS 275 KB + CSS 23 KB + 字体） |
| 依赖 | **零新增**。不需要 pip、不需要 Node 运行时，浏览器直接加载 |
| 渲染入口 | `web/static/math.js` 的 `setRichText()`，替换原来的 `textContent` 赋值 |
| 覆盖 | `$...$`、`$$...$$`、`\(...\)`、`\[...\]` + Markdown 表格 |
| 静态服务 | 改造 `web/server.py`，支持子目录与 woff2/woff/ttf，并挡住 `../` 穿越 |
| 验证 | 40 道入库题的 **199 条公式全部渲染成功**（用 KaTeX 本体跑，不是目测） |

新增预览页 `/static/ext.html`，把 40 道外部题列出来。
主流程（答题页）碰不到这些题，没有这个页面就无法验证渲染是否生效。

### S2.2 数据清理：已完成

| 项 | 结果 |
|---|---|
| 错字修复 | `data/text_fixes.json`，8 条一一对应规则（粗圆→椭圆、圆雉→圆锥、己知→已知…） |
| 修复效果 | 40 道题里 4 处错字清零，条数不变 |
| LaTeX 破损检测 | 定界符不成对 / 花括号不成对 → 拒收 |
| 裸 LaTeX | 全池 0.8%（初中）–1.5%（高中），**一律拒收**，不在前端猜边界 |
| 公式可渲染性 | 新增 `tools/check_formulas.js`，用 KaTeX 本体批量校验，坏题拒收 |

### 公式失败率（实测，决定扩量策略）

| 范围 | 公式数 | 失败 | 涉及题目 |
|---|---|---|---|
| 高中全池 | 33114 | 572（1.7%） | **516 / 6349（8.1%）** |
| 抽样 2000 道 | 10294 | 159（1.5%） | 153 / 2000（7.7%） |
| 已入库 40 道 | 199 | **0** | 0 |

失败主因是源数据里的 `\qquad \`（尾部反斜杠）和 `\Varangle` 这类非标准命令。

**结论：约 8% 的题会因为公式问题被拒。** 这个损失可以接受——
剩 92% 仍然远超缺口（高中需要 97 道，可用池 6349 道）。
但这个检查必须做成自动闸门，否则扩到初中/小学时会把乱码题放进去。
