## 获取与运行

使用包含本轮提交的工作树、Git bundle 或源码 ZIP。在项目目录执行：

```bash
python -m pip install -r requirements-dev.txt
python tools/build_project.py --write
python web/server.py --port 8765
```

打开 <http://127.0.0.1:8765>。HTTP 使用 Python 标准库，档案完整备份使用固定版本的 `cryptography`；构建与结构验收使用固定版本的 JSON Schema 依赖。源码 ZIP 不包含实际学习记录、运行数据库、`node_modules` 或未登记外部题库。

可重建内容使用 `python tools/build_project.py --check` 检查。完整固定版本验收需要真实 Git 基线历史；从 bundle 恢复、安装浏览器和打包的顺序见 [发布流程](release-workflow.md)。核心报告在 `build/regression_report.json`，浏览器报告在 `build/browser-check/report.json`；读取时先核对提交、发布清单哈希、干净状态和完整检查集合。

## 编辑与构建

题源是 23 册 `data/content/` 和 `data/question_sources/application.json`；讲解、单元、实践分别直接编辑 `data/teach/`、`data/learning_units/`、`data/projects/`。逐目标观察计划和新任务由 `data/assessments/` 的四份作者源明确登记。稳定技能及任务契约位于 `data/skills/`，正式教材来源由 `data/content_sources.json` 登记。

编辑后执行 `python tools/build_project.py --write`。不要直接修派生的 `questions.json` 或 `catalog.json`，也不要再运行已封存的旧补全写入器。作者入口、契约归属和退役兼容规则见 [作者工作流](authoring-workflow.md)。

教材位置、技能和任务保留各自稳定 ID。有限目标与相关综合目标并存，不能根据相近标题自动建立细化或先修关系。只提交一个数值或选择，不能证明未提交的建模、证明、作图、口头说明或方法选择；自检要求补写过程也不自动增加新题族。V7 曾新增单元导数确认题 `derivative_monotonicity:transfer-7`，该旧任务和过程待查看规则继续保留。V8 的 1,912 个新任务使用独立观察任务契约，分别明确目标、分项、题族、阶段和未观察范围。[观察任务审查](reviews/v8-identity-integration-review.json)

已声明题族的等价关系写入 `data/task_family_aliases.json`；原未知题族的逐题历史比较写入 `data/task_family_history.json`。V7 的 624 条历史关系继续仅作已接触、有帮助、重复的保守负向比较，9 条实际结构改变的旧未知族任务明确排除。V8 对 `m1b.2.4-q2` 的分类纠正另用 `data/task_family_transitions.json` 按确切任务和旧／新合同续接保守曝光，没有把整个移去关系族合并到静态部分关系。原事件、旧分类和正确性不回填，不进位与进位、直接求剩余与倒推原量等不同结构不能因泛化名称而合并。

修改题面须一起核对答案、`accept`、实际生效的答案契约、题族和观察范围，不能只重算 `verify`。V8 修正 52 条原题作者对象，答案变化为 0；51 条涉及准入指纹续接，另 1 条仅纠正难度说明，全部用途保持。V7 的七个答案变化仍按当时旧／新合同分别保存，不批量重判历史。[当前准入续接](reviews/v8-admission-bindings-review.json) · [V7 答案变化历史](quality-v7-continuation.md#七个答案变化的具体原因)

## 学习判断与下一步

新诊断只为实际作答目标产生本次观察，未作答祖先保持未观察。旧版本 `assumed` 保留作历史原记录，界面标为“旧推断（未实测）”。先修关系是检查基础的路线，不是已有掌握证据。

3,091 道活跃题中 1,731 道保留显式暂定诊断用途；全部活跃题的 `may_confirm_mastery`、`may_judge_weak` 仍为 `false`。补齐元数据没有扩大这些用途。有限目标成功不为未观察的综合目标产生证据，完成单元中的一道题也不解除其他目标的先修检查。[当前目录与策略](../data/catalog.json)

学习计划按具体目标的实际记录安排先修、继续指导和后续观察。没有答题或仅答对探针的未完成指导也保留继续入口，不需要先制造错误事项。候选任务先给不同题族机会，再安排同族变式，避免大量换数题挤占短列表。帮助后答对、同族重复和独立后续观察分开；缺少合适后续题时提供练习并保留待观察事项，不生成空检查或自动宣告解决。

104 项支持均有辨别、三层提示、指导和确认，全部具备两条作者写明的错误路线。提示曝光只记录实际展开层级及所选路线用到的主族／辅助族，未展示的后续确认题或其他错误路线不提前算作已见。旧快照缺少精细声明时保留原来的有限归因，不用新版作者文件重写历史。[支持数学审查](reviews/v7-instructional-support-completion-ai-review.json) · [运行边界](reviews/v7-runtime-continuation-review.json)

新增分项计划为全部目标提供实际可启动任务。共享任务从当前目标进入，作品与导出按该目标的冻结分项组织；含计算结果的私有量规和题族比较理由不会随目标导航泄露。结果页分别显示本题结果已记录、过程待查看及尚未观察。一个分项答对不会自动完成其他分项或整个父目标；解析中的主方法与附带方法仅在对应反馈实际释放后记录曝光。[V8 过程与历史记录审查](reviews/v8-observation-engineering-review.json)

## 学习资产与恢复

匿名学习记录默认保存在 `var/learning.sqlite`，可用 `CNKG_LEARNING_DB` 指定其他位置。发布内容库是 `build/kg.sqlite`，两者独立；构建程序拒绝覆盖学习数据库。

逐目标自检分别保存原作答、困难辨别和重新尝试。指导中的未提交选择和文本也进入所有者隔离、带修订和幂等键的作品存储；新建或空草稿不伪造成绩或错误。打开帮助前先保存原过程，请求后确认保存；失败或 409 冲突保留输入，新提示保持关闭。完全相同的已提交答案重试返回原反馈和下一题，不重复判分或追加答题事件；改变已提交答案仍是冲突。[草稿与重试审查](reviews/v7-runtime-continuation-review.json)

历史作品使用原题面、量规、帮助、参考和 SVG 快照。保存的旧摘要直接使用；缺少摘要只展示原有记录并说明缺失，不调用当前引擎补算。没有可恢复当前题的未完成旧记录保持阻塞和未完成；缺少提示或答案字段时不能显示当前新版帮助，也不制造参考曝光。当前内容更新可以提供新版入口，但不回填旧快照或重判旧答案；评分程序不兼容时明确说明续做限制。

作品、过程草稿、实践步骤、反思与自评有修订历史。自查按全部量规项目统计，未检查项或只写备注仍会提示；学生自评不改写自动判分。浏览器地址保留具体会话 ID，刷新不再次创建检查。切换页面先处理未保存内容，输入框在原记录成功恢复后启用。

V8 新过程入口可把真实图稿或操作照片（PNG、JPEG、WebP）以及录音（WAV、WebM、Ogg、MP4）附在具体分项上。每个文件最多 500 KB，每份作品合计 750 KB、最多 6 个文件；保存原字节、媒体类型、长度和 SHA-256。文件头与哈希检查验证保存一致性，不评判数学内容。删附件只影响后续修订，旧版本仍保留原文件；刷新、回看、导出和完整加密备份恢复均使用冻结资料。未提交实际作品的过程仍未观察。[分项与真实文件说明](quality-v8-continuation.md#过程如何留下可查看的证据)

学习库使用事务维护派生索引，原始会话、作品、历史修订与事件 JSON 保持可追溯。导出 schema 3 包含已呈现题目的冻结题面、选项、图示和相应公开观察分项，仍隔离未呈现题、私有量规及尚未公开的反馈。旧会话不从当前作者源补造分项。该导出用于阅读核查；可恢复的完整备份从“档案与恢复”下载，以恢复码加密。换浏览器、清理浏览器和全新环境导入见 [恢复与迁移](profile-recovery.md)。

“待解决事项”保留跨会话、阶段、版本及学段的历史来源，暂缓须有理由。四种操作工具先记录预测，再检验并保存操作；限定方程案例保留逐步反馈和原配置。备份页区分生成文件、实际文件核验和最新资产是否一致，服务生成文件不等于用户已经保存。
