# 学习流程、证据与作品记录

本轮交付把教材讲解、细目标单元、题目和实践活动接入同一套任务契约。教材位置用于查找内容，稳定技能 ID 用于记录目标。旧教材目标仍标为复合目标；只有实际拆解的目标标为 `observable`，不会把教材节点数量当成独立技能覆盖率。

## 学生可完成的流程

1. 在首页选择学段，查看已有任务、保存的作品和建议的下一步。
2. 从教材页或学习单元阅读讲解，按需要回看明确关联的基础单元。
3. 在自检框写思路。草稿自动保存，也可手动保存、逐项自评、写反思和查看历史版本。
4. 完成练习，立即查看反馈；迁移和复测任务在整组完成后显示答案与解析。
5. 过程题保留原作答，结果页可按量规自查、补充依据和修订。自评不会把原来的 `needs_review` 改成 `correct`。
6. 实践项目按步骤留下作品，再保存反思与自评。离开页面或重启服务后，可以从作品列表恢复。
7. 首页依据已保存活动建议继续、再练习、迁移或间隔复测。1、3、7 天是产品默认规则，尚不是通过真实学习数据校准的自适应模型。

独立教师审核和真实学生效果验证按本轮要求暂缓。它们不阻塞上述工作流，现有元数据也不会把暂缓项写成已完成。

## 题目与材料曝光

服务端分别记录：提供材料、客户端报告展开参考、呈现题目、提交答案和放出反馈。它们说明系统提供了什么、何时提供；不证明实际阅读、理解或独立作答。

材料的 `family_ids` 只包含已提供的例题和自检参考。未呈现的评价题族单列，不因为“关联到同一课”而一并算作看过。项目步骤和直接打开的自检作品编辑器也会记录实际提供的题面，避免绕过教材入口后遗漏曝光。

新题检查排除本浏览器已呈现的题，以及已有声明题族曝光的题。仅换数字、相同结构的题按同族处理。未完成分族的旧题保留 `unclassified`，不同题号不能证明独立性。检查题耗尽时提供可重复的复习练习，不再创建零题检查冒充完成。

延迟复测记录同一范围前次完成的时间、实际间隔及是否达到 24 小时。立即做复测题可以继续练习，但不会被标为已经获得延迟保持证据。

V3由服务端选择同一范围最近的完成记录，旧页面传来的前次会话ID只保留为请求来源，不能绕过较新的记录。还检查同范围最近的材料／参考提供、题目呈现、作答和反馈，分别记录“距前次完成”和“距最近相关活动”的秒数；刚打开讲解后做复测不会被包装成没有近期曝光的观察。首页的复习入口可以直接开始任务，不强制先打开讲解。

1／3／7天的推进只计入当前内容版本、实际间隔满足要求且有作答的已完成复测。立即重做、只跳过任务或缺少可信时间的旧记录不推进次数；它们的原始记录仍保留。即使满足时间条件，系统也不声称已经证明独立作答或学习保持。

过程题的自查按量规逐项计算。只写备注、留在“还没检查”或只检查部分项目，都不会让整道题的待自查提示消失。全部项目明确自评后，可报告自查完成；“我已做到”“还需补充”“需要重做”仍是学生自评，不改写原判分。计划读取所有相关作品摘要，不因前1,000份的分页截断而忘记较早作品。

## 内容更新与恢复

新教材题会话保存目标范围、硬先修、所需题目和分层规则的本地快照；单元保存任务和 SVG 原始字节。无关内容更新不会使正在进行的会话失效。题干、答案、选项、任务契约和图示在恢复后仍采用创建会话时的版本。

评分和推断代码的版本另行校验。规则代码变化后，不会悄悄用新规则继续给旧会话判分；旧题目和原作答保留，可以查看和导出。已完成的结论始终读取当时冻结的结果。

作品绑定内容版本和公开任务快照。新内容创建新的作品实例；旧作品仍按原任务继续修订。每次保存追加版本，原作答、原快照和旧修订不会被后来的自评改写。

页面地址会保存具体会话或作品；刷新、前进和后退恢复相应位置，不再次创建同一入口检查。切换学习页面前先处理待保存内容，失败或冲突时保留原编辑器，并提供重试或保留两版的操作。作品尚未恢复成功时输入框保持不可编辑，避免出现能打字却不会保存的状态。

## 数据与接口

匿名学习数据默认位于 `var/learning.sqlite`，通过 `CNKG_LEARNING_DB` 可指定位置。内容数据库位于 `build/kg.sqlite`，重建内容不清空学习数据。学习库当前为v3：从v1先迁移曝光索引，再从v2增加复习资格和修正作品摘要。事务失败会回滚；原会话、作品、历史修订和事件的JSON保持不变，不补造历史时间或题族证据。

| 接口 | 用途 |
| --- | --- |
| `GET /api/plan?stage=primary` | 根据当前浏览器的活动返回可解释的下一步 |
| `GET /api/history?limit=20&offset=0` | 分页查看作答会话 |
| `GET /api/work?kind=self_check&topic_id=...&criterion_index=0` | 获取自检的版本化任务和已有作品 |
| `GET /api/work?kind=project&project_id=...` | 获取实践项目作品 |
| `GET /api/work?kind=session_task&session_id=...&question_id=...` | 继续已呈现任务的过程记录 |
| `POST /api/work` | 以修订号和请求标识保存草稿、反思、自评 |
| `GET /api/works` | 分页查看作品摘要 |
| `GET /api/work/revisions?resource_id=...` | 查看作品修订历史 |
| `GET /api/export` | 导出会话、已呈现题目的冻结内容、事件和作品全部修订 |

所有读取和更新都以匿名浏览器所有者隔离。作品内容版本、来源和快照由服务端确定；客户端提交的伪造评分或快照不会生效。重复请求可重试，过期修订返回冲突，保留服务器已有版本和浏览器中的未保存草稿；选择“保留两版并保存”且保存成功后，才会追加新的历史修订。浏览器不会自动覆盖另一个页面的较新内容。

导出格式为schema 3，包含已呈现题目的原题面、选项顺序、稳定选项ID、评分形式、目标定义和已冻结SVG的字节及哈希。尚未呈现的任务及尚未公开的反馈不会随导出提前放出。旧记录没有图示字节时明确报告缺失，不用当前图片假冒旧版本。该JSON用于独立阅读和核查记录，不是可直接导回应用的数据库备份。
