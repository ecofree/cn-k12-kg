# 设计决策记录（ADR）

## D1. 不复制 cn-math-taxonomy 的数据，只借结构与算法

**背景**：`xiaoyang111222/cn-math-taxonomy` 有 1821 个知识点、2917 条先修边、7431 道题，规模远大于本项目。但：

- 协议是 **CC BY-NC 4.0**，商用需授权，衍生作品仍受非商业约束；
- 数据对齐的是 2012 版旧教材（issue #5 已指出 2026 年 9 月新版教材发布），七上是 4 章结构，与 2024 版的 6 章对不上；
- README 自述"AI 生成初稿，未经任何教师审核"，且诊断结果页的 AI 声明在 2026-10-22 的提交里被移除。

**决策**：从人教版 2024 版目录重新建点，id 体系、字段结构、判定算法参考其设计，数据一行不取。

**代价**：规模小（28 vs 1821），需要自己写题。**收益**：协议干净、版本正确、每条边都能追溯到教材章节。

## D2. id 编码行政层级，name 只做展示

**背景**：跨学段存在同名知识点（"平均数"小学 `cnm_p129` 与初中 `cnm_211`），按 name 关联一定出错；教材改版时章节编号也会变。

**决策**：`m<年级><册>.<章>.<节>[.<子节>]`，如 `m7a.5.2`。章节号进 id，`chapter`/`section` 存全名用于展示，两者由 `validate.py` 交叉校验。

**代价**：教材改版若调整章序，需要迁移脚本。**缓解**：`curriculum_version` + `edition` 字段进每一条记录，迁移时按版本筛选。

## D3. 数值题强制 `verify` 表达式

**背景**：LLM 生成的题，答案最容易错，而人工复核成本最高。

**决策**：`type=numeric` 的题必须带 `verify`（如 `"(7+5)/3"`），由 `cnkg/verify.py` 在 AST 白名单沙箱中求值后与 `answer` 比对。选择题没有可验算的表达式，标为 `unverifiable`，单独统计，不假装它通过了。

**代价**：写题时多一步；纯文字答案（如"两两垂直"）无法验算。**收益**：91 题里 55 题机器可验，0 不一致；扩题时错误会被自动挡住。

**安全**：只允许数字常量、四则运算、乘方、取模与 `abs/round/min/max/sqrt`，禁止属性访问、下标、推导式、关键字参数、名字注入；幂次上限 12。测试里有 6 个注入用例。

## D4. JSON 是唯一真源，SQLite 是派生产物

**决策**：`data/*.json` 手写维护，`build/kg.sqlite` 由 `tools/build_db.py` 全量重建，随时可删。

**理由**：JSON 便于 diff 和 code review（这个项目的数据需要教师逐条审），SQLite 只负责查询性能与递归 CTE。manifest 记录每个文件的 SHA-256，便于确认"审的是哪一版"。

**代价**：不能直接在库里改数据。**收益**：每次改动都留下可审计的文本差异。

## D5. 判定规则：2 题封顶，hard 优先回溯，升难度必须显式标记

**规则**：
- 第 1 题对 → 掌握，并把全部祖先标 `assumed`（不再出题）；
- 第 1 题错、第 2 题对 → `shaky`，不回溯；
- 两题都错 → `weak`，把未判定的直接先修插到队首，hard 在前；
- 同强度先修按"离目标更近"优先（文件序倒序），因为回溯先查最近一层更省题。

**升难度例外**：题库里没有同级或更易的题时，允许用更难的题，但记 `escalated` 计数并在 CLI 里提示。原因是：宁可显式暴露题库薄，也不要静默地把学生判成薄弱。第一版有 7 个知识点命中这条（每点只有 1 道入口档题）；补了 7 道入口档题后降为 0，并由 `tests/test_engine.py::test_every_topic_has_two_entry_level_questions` 守住。

**为什么不直接上 IRT/BKT**：没有真实作答数据，任何参数都是编的。先用可解释的规则跑通闭环，等有数据再换模型。

## D6. 课标只做映射位，不冒充原文

**决策**：`standards.json` 里每条是自撰摘要，`verbatim: false`、`page_or_ref: "待核"`。`validate.py` 发现 `verbatim: true` 会警告，要求先核对原文。

**理由**：课标条款的准确文本只能从教育部 PDF 逐页核对，凭记忆写等于制造假引用。结构先立起来，文本后补。

## D7. 框架先行：先立 111 个骨架点，再逐册填内容

**背景**：第一版只做了七上 28 个点就准备往下写，风险是后面扩章时发现结构不对、前面全返工（参考项目正好踩过教材版本的坑）。

**决策**：把 6 册 34 章 111 个叶子小节一次性立成 `review_status: "skeleton"` 的知识点，内容字段留空；`validate.py` 按状态分级校验——骨架点只查结构，`draft` 点才要求先修边和题目。

**配套**：
- `fetch_toc.py` 抓目录 → `build_outline.py` 整理成 `outline.json` → `scaffold.py` 幂等补点；
- `outline.json` 是目录的唯一真源，知识点必须与叶子一一对应，多一个少一个都报错；
- Web 端对骨架点显示「待建」并禁用诊断，避免点进去没题。

**代价**：仓库里长期存在 83 个空点，`stats` 看着比例难看。**收益**：扩章变成纯增量，且随时能看到「框架 111 / 已填 28」这个真实进度。

**为什么不等内容写完再建**：内容是按册推进的，而结构必须一次对齐。先把"要做什么"钉死，再决定"先做哪个"。

## D8. 一次把 K12 全学段立全，但按学段分级粒度

**背景**：先建初中再补小学高中，会在"小学要不要拆到课时级""高中算不算 K12"这类问题上反复返工。

**决策**：一次立全 20 个册次、111 章/单元、308 个点，但三个学段的粒度不同：

| 学段 | 粒度 | 理由 |
|---|---|---|
| 小学 | 课时优先、单元兜底 | 抓到真实课时条目就按课时建；只有单元名时按单元建，绝不凭想象补课时 |
| 初中 | 小节 | 有稳定的 1.1 / 1.2.1 编号 |
| 高中 | 小节 | 人教 A 版 1.1 / 1.4.1 编号稳定 |

**第一版曾一律按单元建小学**（50 点），理由是“单元下混着综合与实践”。实测发现这个理由只对一部分册次成立：一上、一下、二上、三上、三下的条目是真实课时（「1～5 的认识」「十几减 9」「乘法的初步认识」），一刀切按单元建等于丢掉了教材自己的教学顺序。改判据后小学扩到 151 点，其中 5 册到课时、4 册（二下、四上、五上、六上）仍按单元。

**代价**：同一学段内粒度不齐，四上「多边形的面积」把平行四边形、三角形、梯形合在一个点里，定位不到具体哪一类不会。**收益**：凡是能对齐教材的地方就对齐，而不是为了整齐去编。**

**过滤规则**：复习单元（复习与关联、整理和复习）不建点；活动类条目不建点，关键词见 `tools/build_outline.py` 的 `ACTIVITY_WORDS`（小讲堂、数学游戏、☆ 主题实践、购物街、故事、编码、称重、身体尺等）。注意「分类与整理」「数据的收集与整理」是真实单元，不能被“整理”二字误杀——第一版就踩过这个坑。

**配套**：`outline.json` 每个册次带 `granularity` 与 `curriculum_version`；`scaffold.py --sync` 保证目录改名能同步到骨架点。

## D9. 版本字段按册次区分，不用一个全局值

**背景**：小学、初中已换 2024 版新教材，高中仍是 2019 版人教 A 版。

**决策**：`curriculum_version` 写在每条知识点上，值由所属册次决定（小学/初中 `2024`，高中 `2019`）；`validate.py` 与 `outline.json` 比对，不一致直接报错。

**理由**：把"2019 版高中"标成 2024 会造成事实错误，而且这种错误在数据里不会自己暴露。

## D10. 先修边按“知识依赖”而非“图形性质”建

**背景**：填九上时，曾把「圆的有关概念」的先修设为「图形的轴对称」，理由是“圆是轴对称图形”。用全错样本跑诊断，根因被判成「图形的轴对称」——学生连圆是什么都没搞清，却被指向轴对称。

**决策**：先修边只表达“学不会 B 是因为没掌握 A”的因果关系。圆的概念依赖的是“到定点的距离等于定长”，即线段长度；轴对称是圆的**性质**，属于「圆的有关性质」之后的内容，不能反过来当先修。

**判据**：建边时问一句“这个前置没学好，是否必然导致当前点学不会”。若只是“相关”“可以类比”“有相同名称”，最多用 soft，且不能跨学段乱挂。

**代价**：调整后单点全错的回溯链变长（会走到线段），但这是真实的知识起点，比给出一个听起来高级的错答案要好。

## D11. 抓不到细目录时，用可追溯的覆盖文件补，而不是放弃或猜

**背景**：2027 春版四册（四下、五下、六下、九下）在电子课本网上还是 404；二下、四上、五上、六上虽已上线，但只给到单元名。若就此停住，框架会永远缺 4 册、7 册停在单元级。

**决策**：新增 `data/outline.override.json`，人工核对后写入章—节—叶结构，`build_outline.py` 优先读它。每条记录必带 `source`（具体到哪个站点/文档）和 `note`（为什么这样建、哪些条目不建点）。

**采信判据**（三条同时满足才写进 override）：

1. **章名与教育部审定 2024 目录一致**。审定目录里四下是「除数是两位数的除法 / 混合运算和运算律 / 三角形 / 小数的认识 / 小数的加法和减法 / 平均数」，不是旧版的「四则运算 / 观察物体（二） / 运算定律」。
2. **至少两个独立来源**。四上、五上靠“教辅目录 + 教研教学计划”，九下靠“教辅平台章节目录 + 省教研院结构表”。
3. **发布时间与教材进度匹配**。2026 年 8 月发布的“2026-2027 学年四下新教材教学设计”，此时教材尚未印发，其目录又与 2012 版高度雷同——判为旧版翻新，不采信。

**典型陷阱**：搜索“四下 新教材 目录”能搜到大量结果，标题都带“新教材”“2024版”，打开却是旧版单元。判断依据不是标题，是章名。这类资料若直接用，会把整个下册建成错误结构，而且因为“看起来有来源”，错误极难被发现。

**代价**：override 是人工维护的，教材正式印发后需要回来替换。**收益**：4 册不再是空白，7 册的粒度与真实教材对齐，且每一条都能追溯到一个具体来源。

## D12. 拿不到真实答题数据时，先用虚拟学生把判定规则量出来

**背景**：计划用 XES3G5M（7652 题 / 865 KC / 555 万交互）校准，但数据在 Google Drive，本机完全不通（`drive.google.com` 与 `google.com` 均返回 000）。ASSISTments、Junyi 的镜像同样依赖境外站点。

**替代方案**：`tools/simulate.py` 构造"知道真实掌握状态"的虚拟学生——按拓扑序生成掌握状态（hard 先修都会则当前点 85% 会，否则 15%），再以 5% 概率随机翻转模拟跳级学会与意外遗忘；答题按"掌握者失误 slip、未掌握者猜对 guess"生成；然后让引擎判定，与真值比对。

**它验证什么、不验证什么**：
- 验证的是**判定规则的逻辑正确性**（漏诊率、根因命中率、规则对称性）。
- **不验证题目难度是否准确**，也不给出任何关于真实学生的分布结论。虚拟学生的参数是假设，不是测量。

**量出来的五个问题**（基准 slip=0.08 / guess=0.2）：

| # | 问题 | 证据 |
|---|---|---|
| 1 | 第 1 题答对即判掌握，漏诊率约等于"没掌握者猜对"的概率 | 19.2% |
| 2 | 代码回溯所有先修边，而 README 写的是"沿 hard 回溯"——soft 边把根因带到无关分支 | 手查 3 个案例，2 例根因落在 soft 分支上 |
| 3 | "不稳"不往回追，一次猜对就把根因截断在中途 | 根因命中 32% → 53% |
| 4 | 根因只从"薄弱"里选，"上游只有一个不稳点"时永远报不出来 | 53% → 66.5% |
| 5 | 一对错不对称：先对后错判"薄弱"，先错后对判"不稳" | 由测试 `test_first_correct_then_wrong_is_shaky` 抓出 |

**改动后的数据**：漏诊 19.2%→7.2%，根因命中 32.0%→66.5%，健康学生假警报 8.1%→10.8%，平均题量 2.14→3.92。

**接受的代价**：题量涨 83%（单点诊断从 2 题到 4 题），假警报涨 2.7 个点。判断依据是两类错误的危害不对称——漏诊会让家长以为孩子没问题，而多问一题只是多花一分钟。

**口径提醒**：本条里的根因命中 78.7% 用的是当时「最高未掌握祖先」的真值定义，D14 已修正为「连续缺口链顶端」，新口径下的数字见 D14。

**仍未解决**：高噪声（slip=0.15、guess=0.35）下漏诊仍达 24.4%。真正的解法是降低 guess——即少用四选一、多用填空与分步作答，这属于题库改造，不是引擎能解决的。

## D13. 猜测率是漏诊的主因，靠题型结构解决，不靠调判定规则

**先纠正一个记录错误**：上一轮我说"989 道题里 700 多道是选择题"，这是记错了。实测是 422 道四选一、567 道数值题（43% vs 57%）。真正的结构性问题不是"选择题太多"，而是**88 个知识点的入口题全是四选一**（占 477 个点的 18.4%）——学生一上来就能靠 25% 的概率蒙对，然后被判定为"掌握"。

**猜测率要按题型算，不能一刀切**。D12 那一轮把所有题统一按 guess=0.2 模拟，等于高估了数值题的可猜性（写错就是错），又低估了四选一的 25%。改成按题型计：

| 题型 | 猜测率 | 依据 |
|---|---|---|
| 四选一 | 25%（基础题 ×1.25） | 4 个选项等可能 |
| 数值填空 | 3% | 只在 0/1/±1 这类边界值上可能蒙对 |
| 短答（填一个词） | 3% | 需要写出具体术语，随机命中率接近 0 |

**做了三件事**：

1. **选题优先低猜测题型**（`engine.TYPE_GUESS` + `_by_guess`）。同级题里数值/短答优先，不增加任何题量。
2. **给 88 个入口全四选一的知识点各补一道入口题**：23 道数值（带 `verify`，能真算的才用）、65 道短答。小学 23、初中 15、高中 50。
3. **新增 `short` 题型**：答案 + 显式 `accept` 列表，判分只做形式归一（全角转半角、去空白、去句末标点、数字按数值比），**不做同义模糊匹配**——"差不多算对"会让猜测率统计失真，同义写法必须人写进 accept。

**效果（敏感性分析，虚拟学生 500 名）**：

| | 全部当四选一 | 现在 |
|---|---|---|
| 平均猜测率暴露 | 31.2% | **13.7%** |
| 漏诊率 | 10.8% | **0.5%** |
| 根因命中 | 58.8% | **78.7%** |

**代价与边界**：

- 65 道短答题无法机器验算数学过程，只能精确比对答案，`verify_questions.py` 把它们计为 unverifiable（现在 487 道）。答案对不对，仍需人工过一遍。
- 短答要求打字，对低年级学生比点选项慢。因此答案控制在 1—6 个字（实测 55/65 条 ≤3 字，2 条 7 字是"充分不必要条件"这种术语）。
- **没有强行转换剩下的 422 道选择题**。机械转换的前提是正确选项本身是纯数字，实测只有 38 道满足；其余正确选项是"0 既不是正数也不是负数"这类句子，硬转成填空会变成默写。这类题的猜测率只能靠"答对后再确认一题"压，不靠改题型。

**顺带修的**：`apply_content.py` 增加 `--update`。之前同 id 题目会被静默跳过，导致内容文件改了却进不了库——这次改题干时就踩到了，4 条重复题干一直报错，直到加了开关才打通。默认仍然跳过，避免误覆盖。

## D14. 不补 449 道 standard 题：难度阶梯的收益被高估，代价被低估

**背景**：全库 1077 道题里 1042 道是 basic，只有 35 道 standard，且第 2 题被限制在「不高于第 1 题难度」——难度阶梯在引擎里几乎不起作用。直觉上该给每个点补一道 standard 题（449 道），让「一错一对」能区分「会基础但不会迁移」。

**做法**：先不写题，用 `tools/ladder_experiment.py` 做假设实验——在内存里给 449 个点各注入一道 standard 题，打开「答对后升一档确认」，跑 5 个种子取均值。

| 配置 | 三档准确率 | 根因命中 | 漏诊 | 题量 |
|---|---|---|---|---|
| A 现状 | 71.1% ±1.7% | 73.5% | 3.2% | 5.46 |
| B 补标准题 + 升档确认 | 70.2% ±1.7% | 65.8% | 0.9% | 6.50 |
| C 补标准题但不升档 | 71.1% ±1.7% | 73.5% | 3.2% | 5.46 |

**结论：不补。** 三档准确率反而降 0.9 个点（±1.7% 噪声内），根因命中掉 7.7 个点，每题多问 1.04 题。

**注**：D17 修正先修边后重测，绝对值为 A 71.9% / B 69.8%（根因 68.7% / 66.9%），结论不变——升档仍然不划算。唯一真实收益是漏诊 2.5%→0.7%，但代价是根因定位变差——而根因才是这个项目的核心承诺。`STEP_UP_ON_CORRECT` 因此默认 `False`，代码留着，等题目难度被真实数据校准过再评估。

**C 组是必要的对照**：单跑 B 会以为「+3 个点是补题的功劳」，其实 C 与 A 完全一致，说明补题本身（不改规则）毫无作用。第一次单种子跑出 +3.8 个点，是随机数流分叉造成的假象——**任何规则或题库对比都必须多种子**。

**同时修正了两个真值口径错误**（它们让此前公布的数字偏悲观）：

1. **根因**：原来取「所有未掌握 hard 祖先里最高的那个」。但学生可能跳级掌握了中间节点，此时更远的祖先并不解释当前问题。改成「从目标沿 hard 边往上、连续的未掌握链的顶端」后，无噪声条件下根因命中从 87.4% 升到 98.5%——引擎一直判得对，是尺子错了。
2. **可演示掌握**：难度感知模型里，能力过低的学生即使标成「学过」也做不对基础题。真值改为「theta > -1.2 才算会」，否则会把引擎的正确判断算成错误。

修正后：布尔模型根因 84.8%、漏诊 0.9%；难度感知模型根因 73.5%、三档 71.1%、二档 86.2%（猜测率按实际选项数计）。

**产品含义**：二档（会不会）86.2% 明显高于三档（会 / 不稳 / 薄弱）71.1%。「不稳」这个标签的信息量有限，界面上必须继续标成「线索」，不能当成结论。要提升三档精度，靠加更难的题没用，得加**同一难度的第二道独立题**（降低猜测与失误的联合影响），成本同样是每点一道题。

**顺带**：`DESCEND_ON_HARDER_FAILURE`（升档失败不回溯）也一并保留，默认 `False` 与升档关闭一致。实测它在升档打开时并未改善根因（66.0%），说明根因漂移不是「回溯过头」，而是「标准题失手」本身把学生误标成不稳。

## D15. 答案键要打散，两选项题要清掉

**背景**：题库分批手写，正确项习惯性落在 B 上。实测 422 道选择题里 B 占 51%、D 占 3%，「一路选 B」能答对 50%；16 道两选项题里 14 道答案是 B（87.5%），而两选项本身猜中率就是 50%。

**决策**：

1. **两选项题一律改短答**（16 道）。两个选项等于抛硬币，改成一个词的填空，猜中率降到接近 0。
2. **选择题答案键打散**（307 道）。按题号哈希排序后轮流分配目标位置，保证每组近似完全均衡：4 选项组 72/72/71/71，3 选项组 40/40/40。「一路选 B」从 50% 降到 27.6%，与随机水平 27.5% 持平。
3. **写进校验器**：选项少于 3 个、或某键占比超过理想值 8 个百分点，直接 FAILED。

**为什么用「旋转」而不是随机重排**：旋转保留干扰项之间的相对顺序，题干里若出现「A 比 B 大」这类依赖顺序的表述不会被破坏；同时目标位置只由题号哈希决定，跑第二遍时旋转量为 0，天然幂等。

**同步成本**：`balance_options.py` 会同时改 `questions.json` 和 `data/content/*.json`，否则下次 `apply_content --update` 会把顺序改回去。

**没有解决**：3 选项题仍有 120 道（猜中率 33%），补第 4 个干扰项属于内容工作，需人工抽检。

## D16. 复核要有顺手工具，否则 160 道题没人愿意点完

**背景**：`inbox/review.csv` 是给外部复核用的，但直接用 Excel 看 160 行题目、选项、答案、解析，读一题要横向滚动好几次。工具不顺手，复核就会变成"全选 pass"。

**决策**：`tools/build_review_page.py` 生成 `web/static/review.html`，把抽样题嵌进单页：
- 一题一卡，答案与解析直接展开，选择题按 A/B/C/D 竖排；
- 快捷键 `1` 通过、`2` 有问题、`3` 跳过、`↑↓` 切题，标"有问题"时自动聚焦备注框；
- 进度与分类计数固定吸顶；筛选"只看未复核"；
- 导出 CSV 的列与 `inbox/review.csv` 完全一致，导回去就能被 `tools/ingest.py` 吃掉。

**为什么不做成在线提交**：复核意见属于低频、敏感的人工判断，存 localStorage + 导出文件比建账号体系简单得多，也不涉及把学生/家长数据传到哪里去。

**顺带清理**：3 组跨知识点重复题（同一道题出现在两个知识点）改写为各自贴合教学内容的题；「下列说法正确的是哪一个？」是通用题干，不同选项，保留。

## D17. 先修边要能被机器审：方向、强度、死路

**背景**：570 条先修边全是我逐条写的，人眼审不过来。抽查时发现两类系统性问题：

1. **方向颠倒**：`五下·分数的认识 <- 六下·比和比例关系`。比和比例是六下内容，却成了五下的前置。理由写的是"比的基本性质与分数基本性质结构相同"——这是**类比**，不是依赖，而且方向反了。
2. **前置挂错**：`三下·口算除法 <- 二下·加减法各部分间的关系`，理由却是"除法与乘法的互逆关系"。除法和加减法没有因果关系，真正的前置是表内除法。

另外统计出 **42 个知识点只有 soft 先修、没有任何 hard 先修**。按引擎规则（回溯只走 hard），这些点在判为薄弱后不会往上追，等于被当成根节点——但它们的上游其实还有内容。

**做法**：

1. 新增 `tools/apply_graph_fix.py` + `data/graph_fixes.json`，把修改登记成可追溯的清单（每条带 why），而不是直接手改 JSON。工具会同时更新 `dependencies.json` 和所有 `data/content/*.json`，否则下次合并会把强度改回去。
2. 逐条审 42 个点，把其中 **17 条真正的因果依赖升级为 hard**（如「角的概念 ← 直线、射线、线段」：角由两条射线组成，不认识射线就无法定义角）。删除 2 条错误边，新增 4 条（含把颠倒的那条改成正确方向、给「分数的认识」补上三上「进一步认识分数」）。
3. 结果：边 568 → 570，hard 436 → 455，只有 soft 先修的点 42 → 24。

**新增校验**（`tools/validate.py`）：

- hard 先修晚于当前点（按册次→章→节→子节排序）→ **ERROR**；
- soft 先修晚于当前点 → **WARN**；
- 由 `tests/test_validate_order.py` 的 7 个用例守住。

**指标为什么不升反降**：修完后根因命中从 73.5% 掉到 68.7%。这不代表诊断变差——**图和模拟学生是同一份数据生成出来的**：多出 17 条 hard 边后，虚拟学生的掌握状态跟着变（前置不会则当前大概率不会），真实根因链也变长，题目更难追。两组数字不是同一把尺子。

判断依据只能是教学逻辑（角确实依赖射线），不是模拟分数。这条也提醒：**改图之后不要拿旧指标做前后对比**。

**剩下 24 个只有 soft 先修的点**，多数确实只是"相关"（如「近似数 ← 科学记数法」「统计案例 ← 分层抽样」），保持 soft 是对的。但「九上·圆的有关概念 ← 直线、射线、线段」这类定义性依赖仍存疑，等真实学情数据再说，不继续凭感觉升级。

## D18. 重复题要靠两条通道查，不能只查完全相同的题干

**背景**：`validate.py` 原来只查「同知识点内题干完全相同」，跨知识点、以及「换个格式问同一件事」都查不出来。补入口题那一轮就踩了：为了给只有选择题的点补一道低猜测题，我照着原题再写了一遍，只是把选择题改成填空——同一道题在同一个知识点里出现了两次。

**两条通道**：

1. **题干+选项指纹**：选择题把选项算进去。只看题干的话，「下列说法正确的是哪一个」这种通用题干会把几十道不同的题算成 1.00。
2. **仅题干**：专门抓「选择题与短答问同一件事」，这类重复会被选项稀释，通道 1 抓不到。会跳过出现在 3 个以上知识点的通用题干。

相似度用字符二元组 Jaccard（不用编辑距离，速度差一个量级），阈值 0.85。

**查出并修掉的**：

- 跨学段完全重复 1 组：骰子偶数点同时出现在高中「古典概型」与初中「用列举法求概率」；
- 同知识点「换格式重问」9 组：向量合力、正态分布 68.27%、正相关、全面调查优点、正切周期、指数模型、-30° 象限、三视图、普查途径——全部改为同一知识点的不同侧面；
- 另有 3 组跨知识点完全重复（上一轮已改）。

**保留的相似对**都是刻意设计的对照题：8 与 -8 的立方根、矩形与菱形、正相关与负相关、y 轴与 x 轴的斜二测变化。它们相似度高但题目不同，属于"同一模板换参数"，不是重复。

**为什么必须查**：同一个知识点里问两遍，等于这个点在诊断里被加权两次；而且学生答对一次就同时"证明"了两道题，掌握判定会被虚高。

**局限**：只做字面比对，同义改写（「求概率」vs「概率是多少」）能抓到，但「掷骰子」换成「抽卡片」就抓不到。语义级查重需要向量模型，超出当前范围。

**落地**：`validate.py` 增加「跨知识点完全重复（题干+答案+选项）」检查，重复即 ERROR；近似重复用 `tools/find_duplicates.py` 单独跑（两两比对不适合放进每次校验）。

## D19. 打散答案键的脚本把旋转方向写反，216 道答案变成错的

**事故**：为了消除「一路选 B 能答对 50%」的捷径，`tools/balance_options.py` 把选项旋转到目标位置并重贴 A—D。`balance()` 里写的是 `k = (want - old) % n`，正确写法是 `k = (old - want) % n`。

旋转后正确项的实际落点是 `(2*old - want) mod n`，而答案键设成 `want`。于是：
- 4 选项：`want` 与 `old` 同奇偶时侥幸正确，不同奇偶时**偏 2 位**；
- 3 选项：只要发生旋转就必错。

脚本一次运行报告「调整 307 道」，最终 **216 道**答案键指向了错误选项（其余是未旋转或恰好同奇偶）。

**为什么三天没发现**：`validate.py` 只检查「答案字母是否在选项里」，不检查它是否指向正确内容；机器验算只覆盖数值题；选择题没有任何自动校验能判断答案对错。而解析里恰好有 6 条引用了选项字母，重排后一起指错，反而让错误看起来像"解析写错了"。

**怎么发现的**：Astra 复核 160 道抽样题，报「答案与解析矛盾」5 条。顺着查发现 20 道可判定题里 17 道的正确项都在当前答案的 +2 位置，这个比例太整齐，才去读脚本。

**怎么修的**：
1. 用穷举用例证明 `balance()` 在 14/25 组合下会把答案指错（现已改成 `old - want`，并让 `assert` 检查旋转后正确项仍在）。
2. `tools/repair_answer_keys.py` 利用「`c ∈ {a, a+2}`（4 选项）」这个约束生成候选，用解析文本打分，自动判定 151 条、人工确认 253 条。
3. `tools/apply_answer_key_fix.py` 写回，同步主数据与所有内容源文件，输出 `build/answer_key_changes.csv` 供复查。
4. 独立抽检 20 道「答案未变」的题，全部正确。

**教训**：
- **分布均衡不是质量指标**。为了一个统计特征去移动正确项，等于把"看起来整齐"当成"正确"。答案键分布应当由内容决定。
- 变更后必须有一个能证伪它的检查。这次如果先写 `test_balance.py` 的穷举用例，事故根本不会发生——而当时我先写了「一路选 B 降到 27.6%」的庆祝结论。

**现在的分布**：A109 / B106 / C118 / D71（3 选项题不可能落在 D），不再追求均衡。

## D20. 改写题干却沿用旧解析，制造了 10 道「解析串题」

**事故**：为了消除重复题、把两选项题改成填空，我用脚本按 id 覆盖题目的 `prompt` 与 `answer`，但 `explanation` 直接沿用源题。结果解析在解释另一道题：

| m3b.1.1-q3 | 推拉窗滑动 | 「电梯沿直线移动」 |

## D22. 外部回传包按「证据分层」接收，不直接改诊断数据

Astra 回传了 160 条复核结论、865 个真实 KC、78 条课标出处、85 行目录审计。这些数据的信息量不同，落盘位置也必须不同：

## D23. 外部题库只进候选池，且不追「收齐各地区」

调研了一圈公开题库后定下的两条边界。

**第一，选源标准不是「题多」，是「许可干净 + 中文原文 + 有答案 + 无配图依赖」。**

| 源 | 结论 | 原因 |
|---|---|---|
| CMM-Math（BSD-3） | 采用 | 2766 道初中 / 6349 道高中可直接用，答案 100%，解析 100% |
| MM-Math（MIT） | 不采用 | 题干是英文机翻 |
| TAL-SCQ5K（MIT） | 采用（挑战层） | 竞赛题，不进诊断；按板块挂靠，见 D41 |
| GaoKaoMath（MIT） | 不采用 | 仅 124 条且英文 |
| 出卷网爬虫仓 | 不采用 | 声称的 `problems.jsonl` 实际未提交 |
| 中考真题 PDF 站 | 不采用 | 图片/Word 整卷，需 OCR，且版权归原出版方 |

**第二，中考分散不是要解决的问题，是可以用上的特性。**

实测 2025 年中考数学真题汇总页：118 条 listing、约 30 个省级 + 约 36 个地市自主命题，
去重后单年约 60–70 套。要收齐，等于每年啃 60 份 PDF、还要 OCR。

但这个项目根本不需要收齐。当前最大短板是「364 个知识点只有 2 道题，一次诊断就把题库用完」。
需要的是**每个知识点多几道不同问法的题**，不是**每个地区都有一份卷**。
分散恰恰意味着同一知识点有大量地区变体，是好事。

所以：不建「地区真题库」，只建「知识点题池」。

**第三，外部题一律进 `inbox/candidates/`，`topicId: null`、`needs_kc: true`、`review_status: unverified`。**

上一轮我把"结构化中文带解析的源只有 CMM-Math 一个"当成结论，**这是错的**。

| **DxAThing/Gaokao-Math-Problems-Compilation** | 137 | **777 份卷 / 16321 题**（1952–2026） | **LaTeX 源码**，题+答案+解析齐全 | **CC BY-SA 4.0** | **主源，采用** |

### 为什么这个源值得换

| | CMM-Math | 高考 LaTeX 合集 |
|---|---|---|
| 年份 | 无 | **1952–2026** |
| 省份/卷别 | 无 | **有**（2019天津文、2023新高考II卷…） |
| 答案 | 有 | **有，且解析写明"故选 X"**（可交叉核对） |

| 难度 | 无 | 天然分层（年份+卷别） |

### 实测

- 777 份卷全部解析成功，**16321 题**，65% 有答案，97% 有解析
- 2015 年后、有答案、四选项、无配图 → **1152 道单选**可用
- 规则映射命中 506 道、覆盖 64 个知识点；人工判定 43 条候选留 33 条
- 最终入库 **30 道高考真题**，覆盖 **30 个知识点**（其中 20 个是 CMM 没覆盖到的）
- 答案自洽核对：30 道里 24 道解析里的"故选 X"与答案字段一致
- 最终 70 道外部题、457 条公式，**KaTeX 全部渲染成功（0 失败）**

### 踩到的四个坑（都写进代码了）

1. **`\i` 裸替换毁掉 `\item`**。老卷用 `\begin{enumerate} \item`，把 `\i` 替换成 `\mathrm{i}` 后变成 `\mathrm{i}tem`。改成带词边界的正则。
2. **老卷的答案写在 problem 块内部**，新卷写在块外面。解析器要两种都认。
3. **`（\quad）` 不是公式**，是高考卷的填空标记。我的"裸 LaTeX"检测把它判成公式，32 道题被误杀。
4. **逐个 HTTP 拉 777 个文件会被代理限流**（502 卡死）。改用
   `git clone --filter=blob:none --sparse` + `sparse-checkout content`，一次 19MB 搞定。

### 中考怎么办

需要工具而不是找源：
- 上海卷是 .doc → 要装 LibreOffice 转换（本机没有 Word，也没有 soffice）
- 各省真题 PDF 多为图片版 → 要 OCR，公式部分只能靠 Mathpix 或 pix2tex
- 网页路线（菁优网逐题抓取）可行且自带知识点标签，但要看站点条款

**结论：高考这条路已经通了，中考需要先决定装不装工具。**

## D28. M3.1 落地：选项身份改成 option_id，字母不再进数据

Astra 在第三轮末尾建议："修复时把答案绑定到稳定 option_id，选项标签在最终显示时生成"。
这条建议直接冲着 D19 事故的根因——**字母既是身份又是显示，重排就必然出错**。

### 改造前后的差别

| | 改造前 | 改造后 |
|---|---|---|
| 选项 | `{"key": "A", "text": "..."}` | `{"id": "o1", "text": "..."}` |
| 答案 | `"B"` | `"o2"` |
| 字母 | 存在数据里 | **只在前端按下标生成** |
| 选项重排 | 要重算答案键，方向写反就全错 | **答案根本不用动** |

### 为什么这是根治而不是打补丁

D19 那次事故的机制是：`balance_options.py` 里 `k = (want - old) % n` 写反了，
一次批量重排让 216 道题的答案指向了错误选项。**只要字母还在数据里，
这类事故就随时可能再发生**——因为"重排"和"改答案"是耦合的。

现在两者解耦了：id 跟着选项走，答案指向 id，重排只是重排数组。
`balance_options.py` 里的旋转方向陷阱**从结构上消失了**，新实现里连方向计算都不需要了。

### 数据迁移

`tools/migrate_option_ids.py`：1077 道自有题里的 404 道选择题 + 70 道外部题 + 14 个内容源文件里的
451 处，共 **925 处**迁移。幂等（已带 id 的跳过）。

**字母彻底从数据里消失**：迁移后 0 处残留 `key` 字段。

### 连带改造的地方

| 位置 | 改动 |
|---|---|
| `web/server.py` | 新增 `option_id_for()`：正常走 id，兼容旧的字母提交（按当前顺序换算） |
| `web/static/app.js` | 字母用 `String.fromCharCode(65 + idx)` 生成，提交 `choice.id` |
| `tools/balance_options.py` | 重排后答案不动，断言正确项仍在目标位 |
| `tools/export_inbox.py` | sidecar 的 `option_id` 直接取数据里的 id，`correct_option_ids` 取答案 id |
| `tools/import_question_bank.py` | 导入时给选项编 id，答案换成 id；答案核对按 id 比较 |
| `tools/build_review_page.py` / `build_ext_page.py` | 字母按下标生成 |
| `tools/validate.py` | 新增硬规则：答案必须在选项 id 内、id 不重复、不许再有 `key` 字段 |

**一个连带的语义修正**：validate 里"答案键偏斜"统计原来数的是字母分布，
现在数的是**正确项落在第几位**——这正是学生看到的分布，统计口径变得更对。

### 验收

- 全部 **404 道选择题**判题：404 正确 / 0 错误
- **打乱选项后判分不变：480/480 通过**（120 题 × 4 个目标位）
- 125 个单元测试通过（含重写后的 `tests/test_balance.py`，把 M3.1 的验收标准写成了断言）
- VALIDATION PASSED、VERIFICATION PASSED、模拟正常（根因命中 83.1%）

### 顺带说明：为什么解析里还留着一处字母

`tests/test_balance.py` 里有一条测试专门验证"字母是位置不是身份"——
重排后同一个字母指向不同选项，判分随之改变。**这正是要靠 id 避免的坑，
但字母仍然保留为兼容输入**，所以旧客户端提交字母也不会立刻失效。

## D29. 中考卷：LibreOffice 能转换，但公式是位图，靠菁优网考点标签解决映射

用户装了 LibreOffice（`D://Program Files\LibreOffice\`，26.8.1.1），
问的是「中考卷这条路走不走得通」。实测结论：**源能用，但有三个必须先说清的限制。**

### 一、GitHub 上中考的结构化语料确实不存在

搜遍 GitHub，上海中考是最完整的一批：`Xnye/Smse`，276 个 .doc + 38 个 .docx + 30 个 PDF，
覆盖 2012–2022 上海各区一模二模，**全部带解析**。但形态是 Word/PDF，不是 LaTeX——
跟高考那个合集（777 份 LaTeX，题+答案+解析齐全）完全不是一个量级。

| | 高考 LaTeX 合集 | 上海中考 .doc |
|---|---|---|
| 形态 | LaTeX 源码 | Word 二进制 |
| 答案 | 有，解析写明「故选 X」 | 有，解析写明「故选：X」 |
| 公式 | **LaTeX 文本** | **位图 PNG** |
| 配图 | 16% | 大量，且与公式混在同一位置 |
| 知识点标签 | 无 | **有（菁优网考点编码）** |

**唯一的下载通路是 `api.github.com` 的 git/blobs。**
git clone 报 TLS 握手失败、codeload tarball 超时、raw 端点间歇性 SSL 错误——
最后靠 raw + 指数退避重试才把 314 个文件拉下来（`tools/fetch_smse.py`）。

### 二、LibreOffice 转换可行，但有两个坑

`soffice.com --headless --convert-to "txt:Text (encoded):UTF8"` 能转，中文、选项、
题号、答案区全部保留。**但必须用 soffice.com 而不是 soffice.exe**（Windows 上
soffice.exe 会脱离控制台，拿不到输出与退出码）；且一次要传多个文件，
因为每次启动 soffice 要 2–4 秒，300 个文件一个一个调要两小时。

**限制一：源 .doc 里的公式是位图。**
二进制里搜不到 Equation / MathType / MTEF 任何一个标记，
LibreOffice 转出的 fodt 里 `draw:object` = 0，说明公式在源文件里就已经是图片了。
所以纯文本导出后公式变成空缺：「若 cosA=√3/2，则∠A…」变成「若，则∠A…」。

**限制二：答案区重复题干，这既是好事也是麻烦。**
好事：题目区与答案区各有一份题干，可以交叉校验；答案区有「故选：X」可作为答案信号。
麻烦：填空题要判对错，解答题无法机器判分——**每卷 25 题里只有 18 题（6 选择 + 12 填空）可用**。

### 三、真正的价值在考点标签，不在题目本身

菁优网给每道题打了考点标签（`S9：相似三角形的判定与性质`、`T5：特殊角的三角函数值`…）。
108 个不同标签，**语义与我的知识点名高度一致**，人工建映射表后可直接落地。

这正好解决了我在 D23 里判定为死路的那件事：**「题→知识点」的语义映射**。
高考 LaTeX 源没有标签，只能靠规则硬猜（精度 83%）；中考卷自带标签，映射是查表。

映射表 `data/kc_tag_map.json`，人工建立 107 条。
建表时踩到的坑：**我按教材顺序推测的知识点 id 全是错的**（101/107 不存在），
实际 id 编码是 `m7b.8.1 平方根` 这种——**映射表必须用真实 id，不能凭推测**。

### 四、公式丢失率：约 7%，可接受

缺口判据不能只看标点。「（　　）」是选择题的答题括号（源数据本来就有），
「若，」才是公式丢失的信号。Python 的 `\s` 会匹配全角空格 U+3000，
所以用 `\s*` 会把答题括号也误判——**必须只认 ASCII 空格**。

判据定为「连接词后直接跟标点」：
`若，` / `计算：＝` / `对于…下列` / `那么等于` / `的结果是` / `下列各式中` / `=后无值`。
6 卷样本实测 151 题 → 保留 75 题（50%），其中误判已经过逐条人工核对。

### 五、超纲题要标出来，不要硬塞

`LM：*平面向量` 在中考卷里出现 10 次——这是**高中内容**，
`H1：二次函数的定义` 也超出初中范围。`圆与圆的位置关系` 在人教版九上是选学，
我的知识点表没有独立条目。

处置：`out_of_scope` 单独列出，不入库。**把高中向量硬塞给某个初中知识点，
比不收这道题危害大得多**——它会让那个知识点的诊断结果失真。

### 六、这一轮的实际收获

6 卷样本（6/314）产出 75 道已归属知识点的题，覆盖 34 个知识点。
按同样比例推算，全量 314 卷可产出约 3900 道，其中约 1000 道是带选项的选择题。

对比初中缺口 87 个点——**量完全够，甚至过剩**。
真正的限制不是题量，是「每份卷子只能用 18/25 题」和「公式丢失 7%」。

- 填空题的答案抽取与校验（答案区有答案，但格式多样，需要单独解析）

### 九、四个必须记住的技术教训

1. **Python 的 `\s` 会匹配全角空格 U+3000**。
   所以「（　　）」这种选择题答题括号会被 `\s*` 误判成「公式丢失」，
   导致 25 道本来完好的选择题被全部拒收。只认 ASCII 空格才对。

2. **`str.isalpha()` 对中文返回 True**。
   上标还原里我用 `head[-1].isalpha()` 判断「前一个字符是不是字母」，
   结果「方程x2」被判成前文是中文 → 跳过还原。必须加 `.isascii()`。

3. **全角括号和小连字符在 KaTeX 里是坏字符**。
   `（` `）` 只会警告，但 `﹣`（U+FE63 小连字符）是**完全无法识别**的，
   会渲染成缺字符号。定界时必须把全角数学符号转成 LaTeX 记号。

4. **解析块的行不能把当前题置空**。
   「故选：X」在 `【解答】` 块里，我一开始把 `【` 开头的行当作段落结束（`cur = None`），
   结果 100% 的选择题丢失答案。正确做法是标记「离开选项阶段」但仍归属当前题。

### 十、这一轮的收获比题量更重要

**「题→知识点」这个老大难，在有标签的源面前根本不是问题。**

- 高考 LaTeX 合集：无标签，规则映射两轮抽样都是 83%，是方法天花板
- 上海中考 Word 卷：自带菁优网考点标签，人工建映射表后**直接查表落地**

同时暴露了自编题库的一个盲区：**44 个初中知识点是上海中考不考的**，
而我们自己的题库在这些点上也只有 2 道。区域题库能照出这个偏差。

## D30. 剩下的缺口不是「题不够」，是「考试不考」

第四轮包交付后，继续挖了两个方向：中考卷全量接入（D29）与高考老卷补量。

### 一、中考年份字段的 bug，以及 2020 年后的第二种版式

**bug**：`paper` 字段取的是转换输出目录（`smse_txt/…`），真实年份目录丢了。
修法不是改目录名，而是**从文件内容里抽年份**——
因为 2020 年后的文件名是「上海市嘉定区2020届…」，年份在中间。

**顺带发现两种版式**：

| 版式 | 特征 | 覆盖年份 |
|---|---|---|
| A（菁优网） | 题目区 …… 参考答案 …… 答案区（重复题干） | 2012–2019 |
| B（另一种排版） | 题目与解析交错，`【答案】C` 紧跟题后 | 2020–2022 |

版式 B 没有「【考点】」编码，只有「【点睛】」自然语言描述
（「本题主要考查相似图形的概念」）。**实测投入产出比太低**：
471 道题里只有 62 道选项+答案完整，其中 43 道能抽出考点描述。
为 43 道题建一套模糊匹配不值得，所以**版式 B 暂不接入**。

### 二、高考老卷：4214 道高质量单选题，但只补了 11 个点

2015 年前的高考卷（1983–2014）有 **4214 道四选项单选题，100% 有解析、99% 含 LaTeX**——
质量远高于中考卷（公式是文本不是位图）。

按 D25 的规矩逐条判：140 条候选 → 人工留 15 条 → 公式闸门拦下 2 条、重复 1 条、裸 LaTeX 1 条
→ **实际入库 11 道**，覆盖 6 个新的高中知识点。

答案位置分布与新卷一样均衡（这批全是四选项）。

### 三、真正重要的发现：39 个「缺口点」里，大部分高考根本不考

补完老卷后，**高中仍有 39 个点只有 2 道题**。逐个查这 39 个点在
16321 道高考真题里的出现情况：

**真正「高考不考」的只有 5 个**（宽松匹配也是 0）：

- 给知识点加 `exam_scope` 字段：`national` / `regional` / `textbook_only`
- 状态报告单独报出「高考不覆盖的缺口点」数量
- 诊断引擎将来可以按 `exam_scope` 过滤

### 四、这一轮的方法论收获

**「缺口」这个概念本身需要分层。** 之前只有一个数字：
「364 个知识点只有 2 道题」，看起来像是要补 364 个点的题。

实际上：
- 180 个是小学的（CMM-Math 有 10382 道小学题，但要查它的答案分布异常）
- 87 个是初中的（中考卷能补 43 个，剩下 44 个主要是上海中考不考的地域性内容）
- 97 个是高中的（高考卷能补 58 个，剩下 39 个里只有 **5 个**是全国卷真不考的）

**外部题库的价值不只是「补题」，更是「照出自己知识库的偏差」。**
上海中考照出了 44 个地域性缺口，全国高考照出了 5 个真·考试范围缺口
（另外 13 个暴露的是我自己词表规则的漏洞——这同样有价值）。
这两种偏差靠自编题库永远发现不了——因为自编题库是自己看着教材编的，
自然会覆盖全部教材内容，却不会意识到考试根本不考其中一部分。

## D31. 真题源解锁：按证据强度分级准入，而不是按来源一刀切

用户指出两件事：①「中考题是公开的题目，不需要许可」；②「高考题目也是」。

**这个纠正是对的。** 中高考真题是公开发布的考试材料，作为教学用途整理
不属于侵权使用。我之前把「仓库自述仅作个人备份 + 题内含菁优网版权声明」
当成了使用限制——那是**过度谨慎**。

但解除许可锁不等于解除全部锁。「未经过第二人复核」这条（D22 立的规矩）
与来源无关，仍然成立。所以改成**按证据强度分级准入**。

### 一、四级准入

| 等级 | 含义 | 能否进诊断 |
|---|---|---|
| `verified` | 有第二人复核过 | 能 |
| `cross-checked` | 两个独立来源互相印证 | **能** |
| `tag-mapped` | 靠标签映射，答案有机器交叉校验 | 不能 |
| `ai-mapped` | 靠规则映射 | 不能 |

各源的实际证据强度（实测，不是估计）：

| 源 | 等级 | 依据 |
|---|---|---|
| 高考真题（gaokao-tex） | **cross-checked** | LaTeX 原生；解析里「故选 X」与答案键 **66% 一致**；其余由题目区/答案区选项文本逐字一致保证（解析器已验证 100% 通过） |
| 上海中考（smse） | **cross-checked** | 答案取自原卷答案区「故选：X」；350 道样本的**题目区/答案区选项文本双向一致 100% 通过** |
| CMM-Math | `tag-mapped` | 无年份地区，答案只有 **42%** 能与解析「故选 X」互相印证 |

**「cross-checked」的确切含义**（重要，别过度解读）：
不是「答案一定对」，而是「答案有两个独立来源互相印证」——
原卷的 answer 字段 + 原卷的解析/答案区。
这比 D19 事故前那批「靠打散选项重算答案键」的题强一个量级。

结果：**167 道真题源解锁进诊断**（题量 1077 → 1244），
**37 个知识点从「只有 2 道题」变成 3 道以上**——
这正是「一次诊断就把题库问完」这个核心痛点的直接改善。

CMM-Math 的 40 道仍然留在诊断外，因为它的证据强度确实最弱。

### 二、Astra 第四轮回传：又抓到 3 处答案键错误

320 题复审（pass 306 / fail 14）+ 20 条复检（pass 19 / fail 1）。

## D32. 题量储备：外部题库不够，记忆型知识点的题必须自己生成

用户提出一个我之前低估的机制：**必要数量的题目是强迫学生记住基础知识（公式、定理）的方式**。

这个论证是对的，而且指出了我设计里的一个盲区。我一直在优化「诊断得准」，
没想过「题不够」本身就是失分原因。

### 一、先把「缺口」量化清楚

### 三、所以记忆型知识点的题只能自己生成

关键突破是发现：**知识点的 `description` 字段已经把公式和定理内容写清楚了**。

- 「平行线的判定」→「同位角相等、内错角相等、同旁内角互补，都可判定两条直线平行」
- 「不等式的性质」→「两边乘同一个负数方向必须改变」

据此生成两类题，共 226 道：

**A. 记忆检验题（86 道，选择题）**
「关于 X，下列说法正确的是」——这是检验「记住了性质本身」的主力题型，
外部题库里几乎不存在。
干扰项两类：**跨知识点张冠李戴**（别的知识点的真实内容）+
**同知识点条件错置**（「垂径定理」写成「平分弦所对的圆周角」）。
后者最贴近真实错误——「记住了但没理解条件」。

**B. 计算练习题（140 道，数值题）**
口诀、笔算、面积周长、估算、小数四则、分数乘整数、百分数、比值等 35 个知识点。
**带 verify 表达式，答案可机器验算**——这是相对 A 类的最大优势。

### 四、verify 表达式当场抓出 8 道错题

|---|---|

四类问题都是「生成逻辑与答案形式不匹配」，纯肉眼看不出来。

### 五、记忆检验题的两版设计（第一版有致命缺陷）

**第一版**：干扰项直接取**同知识点的其它条款**。

如果前半句也在同一句里被改成一样表述，选项就自相矛盾了。
加 `self_contradictory()` 过滤掉。

同点内题干不同 / 答案是纯数字 / 答案位置分散（不能总在同一位置）/

`docs/question-bank-plan.md` 定了储备标准：

## D34. 难度不是标签，是「这道题要走几步」

起因是小学段审计：203 个点里 **74 个只有单一难度**（全是 basic）。
一开始想按内容复杂度人工提档，但小学的策略白纸黑字写着
**难度按步骤数**：basic 一步、standard 两步、advanced 三步。
所以问题不在「怎么标」，而在**题库里压根没有两步题**——
自产计算题每个点 4 道全是一步，外部 CMM 又按长度分位，信号极弱。

### 一、做法：给 57 个可计算点各补一道两步题

`tools/gen_calc_questions.py` 第五批（`STEP2_GENERATORS`）：

- 一年级凑十/十几减几/连减/逆向加法/相差
- 二年级乘法情境/米与厘米/9 的口诀求商/位值组成/万以内连减
- 三年级分数初步（二分之一、几分之一、同分母加减、具体量化比较）
- 四五年级小数（乘整数、乘小数、运算律、除以整数、除以小数）
- 六年级分数（乘整数、除以整数、除以分数、分小混合运算）

**难度不写死**：只保证 verify 至少两步，由 `calibrate_difficulty` 的
`count_steps` 自动给 standard/advanced。写完 57 个生成器后实测
`count_steps` 分布：47 个点两步（standard）、6 个点三步、2 个点五步、
1 个点四步——**全部高于 basic**，承诺兑现而不是嘴上说。

### 二、三条写法纪律（都是踩出来的）

1. **题干不许透露中间结果**。「1 个十和 5 个一合起来是 15，去掉 3」
   这种写法学生只做一步减法，verify 却算两步——名不副实。
   两步题要么用连续两问口径，要么把中间量藏进情境。
2. **答案不许写成分数**。`compare()` 对非数值走字符串比对，
   `"3/4"` 与 `0.75` 永远 mismatch。分数运算一律改成
   「具体量化」框架：不问「3/4 的 1/2 是多少」，问「8 米的 3/8 是多少米」。
3. **分数商必须是有限小数**。`1/3` 这类循环小数经 `_fmt_dec`
   截断后误差 5e-5 > 1e-6 容差。`_s2_div_int` 只取 10 组
   预构造的组合（如 `9/10÷3=0.3`、`1/4÷2=0.125`）。

顺带记录一个 `count_steps` 的既有约定：**括号内的子式先去掉再数**。
所以 `9*(5+6)` 数出 1 步（basic），而 `9*5+9*6` 数出 3 步。
`_s2_frac_dec_mix` 刻意用 `{total}-({total}*{n}/{d})-{r}` 的写法，
让「求一个数的几分之几」作为一个子步被吸收，结果落到 standard 而非 advanced。

### 三、结果

| 指标 | 批 F 前 | 批 F 后 |
|---|---|---|
| 小学单一难度点 | 74 | **17** |
| 小学难度分布（题点对） | — | 62/29/8 |
| 自有计算题 | 593 | **657**（+57 两步题） |

剩余 17 个点是**识别/比较类**（第几、观察立体积木、自选标准分类、
运动现象、用字母表示数、有序数对确定位置……）。它们的全部题型是
choice/short，本来就是「会不会」而非「几步算」——
basic-only 是真实难度，**不硬造梯度**（这才是不注水的意思）。

### 四、守门测试

## D35. 外部题库 4429 个 id 撞车：10628 道题被按 id 的视图静默吞掉

起因是审计 CMM 答案（D36）时的顺带发现。查 id 唯一性时发现：

    ext-cmmmath-00001  六年级  '把一个圆柱的侧面展开, 不可能得到的是'  tag-mapped
    ext-cmmmath-00001  七年级  '2022 的绝对值是'                  tag-mapped
    ext-cmmmath-00001  高二    '已知 sin α > sin β, 下列命题成立的是'  cross-checked（可诊断）

**三条完全不相干的题共用一个 id**，4429 个 id 被 10628 道题共用（2659 个用两次、
1770 个用三次），而且**没有一条是同一道题**。

### 一、根因

`import_mapped.py` 里 `seq = len(imported) + 1` —— 序号按**本轮导入**计数。
CMM 分三批（小学/初中/高中池）导入，每批 seq 都从 1 重数，于是撞车。

### 二、影响面（实测，不是推理）

| 场景 | 是否受影响 |
|---|---|
| 图内存题库（graph.py 按 topicId append 进列表） | 不受影响 |
| 任何 `{q['id']: q}` 视图 | **6199 道题不可见** |
| 其中可诊断题 | **546 道被静默吞掉** |
| store.py 建 SQLite | 靠 `ext-{source}-{id}` 前缀改名躲开主键冲突，代价是库里 id 与 JSON 里对不上 |

### 三、为什么一直没被发现

`validate.py` 的题库校验**只加载 questions.json，从来没看过 questions_ext.json**。
外部题 23313 道（占全库 91%）此前完全不在校验视野里。

### 四、修法

1. `import_mapped.py`：序号改成从**已有数据的最大后缀往后接**
   （`seq_base = max(已有 ext-{prefix}-NNNNN)`），并加 `used_ids` 兜底查重。
2. 新工具 `tools/fix_duplicate_ext_ids.py`：保留首次出现的 id 不变，
   重复项按出现顺序加 `-d2` / `-d3`（只动 6199 条，可复现）。
3. `validate.py` 新增 `check_external()`——外部题也进校验：id 唯一、
   不与自有题撞车、topicId 存在、type/difficulty 合法、题干非空。
   （内容级检查如「题干泄露答案」「accept 列表」留给自有题，
   外部题按准入规则另有 admission 工具管，口径不同不该混。）
4. 新增 `tests/test_ext_ids_unique.py`（5 条）把唯一性钉死。

**修后自检：23313 道题 id 全部唯一，可诊断题在 id-keyed 视图里 9019 道全可见
（此前 9019 里丢 546）。**

## D36. CMM short 题 78% 的答案带噪声，清洗后 50% 可当单值用

`tools/audit_cmm_answers.py` 实测：CMM 小学 4272 道 short 题里
**78% 的答案不是干净的答案值**，形态包括：

- `答案: $-7 \quad+5$`（`$` 定界符 + `\quad`）
- `解$60 万\n\n【分析】…`（前缀 + 整段参考答案）
- `(1) 80 厘米;\n\n(2) 20 厘米`（多小问挤在一个字段里）
- `$\sqrt{ }$`——**这不是根号，是判断题的「√」**（与 `$\times$` 配对，实测 746 条全是判断题）

**落地方式：只增补字段，不改答案原文。** `tools/clean_cmm_answers.py` 写
`answer_clean` + `answer_clean_kind`，`answer` 永远保留——清洗规则再稳也是启发式，
出错时要能回到原文核对。

### 五类判定（全库 7135 道 short）

| 类别 | 题数 | 含义 |
|---|---|---|
| single | 2660 (37%) | 单值，可用于判分 |
| judge | 905 (13%) | 判断词（√/×/对/错） |
| multi | 2170 (30%) | 多值，不可当单值判分 |
| prose | 115 (2%) | 汉字 ≥10 个，是解题思路不是答案 |
| unresolved | 1285 (18%) | 规则不敢动，留给人工 |

**50% 可当作单值判分**（此前 0%——它们连展示都看不成样子）。

### 踩出来的六条规则纪律

1. `\left` 必须在 `\le` **之前**处理，否则 `\left[` 被啃成 `≤ft[`（实测发生）。
   所有命令再加 `(?![a-zA-Z])` 兜底防前缀误吃。
2. `\quad` 是**多空分隔符**不是空格——换成空格会把「-7 \quad +5」伪装成单值。
3. 嵌套分式 `\frac{1}{\frac{2}{3}}` 逐个替换会得到 '1/2/3'（真值 3/2）→ 逐个替换 +
   逐个复查参数，参数里出现 `/` 就整条判 unresolved。
4. 去句末句号**之后**必须再 strip 一次，否则 '故答案为: 236,240 。' 留下尾随空格，
   清洗不幂等（实测 176 条会二次漂移）。
5. 127 条答案里有控制字符（`'$\x0crac{1}{10}$'`，`\frac` 的 `\f` 被存成了真换页符）
   ——源码写坏了，洗不出来，判 unresolved 而不是凑一个值。
6. `\sqrt{ }` 空 radicand 是判断题的 √；有 radicand 的才是真根号（→√2）。

## D37. 把外部题纳入校验：先量再修，修不了的就封存

D35 修完 id 撞车后，外部题终于进了 validate 的视野。但在把自有题那套内容级
规则套上去之前先做了体检（`tools/audit_ext_quality.py`）——**直接开成 error
会一次性炸出上万条，那等于把检查关掉**。体检结果分三类处置：

### 一、完整性：比预想的好（0 违规）

| 体检项 | 命中 |
|---|---|
| 选择题答案不在选项 id 内 | 0 |
| 选项 id 缺失/重复、还留着 key 字段 | 0 |
| 答案为空但不是 compound-reference | 0 |

也就是说「外部题很脏」这个印象是错的——脏的主要是**答案的呈现格式**（D36），
不是结构本身。

### 二、修得动的：全部修掉

| 问题 | 规模 | 处置 |
|---|---|---|
| 选项文本为空 | 17 道 | 6 道「正确答案正指向空选项」+ 11 道残缺 → 封存退出诊断；干扰项上的空项删掉（删完仍 ≥3 项才删）。工具 `repair_empty_options.py` |
| 解析用字母指代选项 | 1184 条解析、1607 处 | 换成**选项内容**指代（「选项 C 符合题意」→「π 倍」符合题意），原文存 `explanation_original`。工具 `fix_explanation_letters.py` |

**字母→内容替换只认高精度写法**：`选项 C`、`C 选项`、`D 项`、`故答案为: D`。

### 三、修不动的：承认为设计取舍，报出来但不让校验失败

- **562 道数值题没有 verify**：外部题靠**来源证据**准入（原卷答案 + 解析互证），

- **10253 道短答题没有 accept**：同义写法会被判错，需要人工/模型做同义归一，

### 四、新增的第四个准入等级：broken

封存残缺题时踩到一个坑：只把 `usable_for_diagnosis` 置 False、不动

否则会把已判残的题重新放回诊断。

### 十、配套改了引擎，否则储备等于白储备

生成题入库后发现两个问题，**都是「储备了但抽不到」**：

**问题一：连续 6 次诊断抽到同一道题。**
题库从每点 2 道扩到 4–7 道后，引擎出题还是「按猜测率排序取第一个」，
同一知识点每次都遇到文件序最靠前的那道。练习模式下学生做十遍都是同一题。

**问题二：记忆检验题永远抽不到。**
`_by_guess` 按猜测率排序，数值题（2%）永远在选择题（25%）之前。
同一点的第 1、2 问都是数值题，记忆检验题排在第三永远轮不上。

1. `_interleave_types`——按题型轮流。

   （这个 bug 我犯了一次才发现）。
2. `_prefer_other_type`——第 2 问避开第 1 问的题型。
3. `rotate` 轮转偏移——服务端维护的会话计数，不用随机数（保证可复现可审计）。

服务端实测：连续 8 次诊断同一知识点 → 抽到 **6 道不同的题**，
题型轮转 numeric → short → choice。

## D38. 指标必须绑口径：一次体检抓出的三套账

### 一、起因

用户要「项目的真实情形，详细审计报告」。我先跑了一遍现成的
`status_report.py` 和 `check_stage_policy.py`，看到的是：
题量下限三学段 0 缺口、单一难度点只剩 17 个、校验全绿、233 测试全过。
如果照抄这些数，报告会写成一封表扬信。

于是另写 `tools/audit_project.py` 直接按「诊断器能不能抽到这道题」重算，
结果对不上：小学题量不足 54 个点、单一难度 130 个点。
追下去发现不是数据变了，是**同一个指标有三套算法**。

### 二、三套账的确切区别

| 口径 | 定义 | 谁在用 | 小学题量不足 |
|---|---|---|---|
| 全库题点对 | 自有 + **全部**外部题，复合题按 `topicIds` 给每个关联点各记一道 | `check_stage_policy` 旧版 | **0** |
| 诊断池题点对 | 自有 + `usable_for_diagnosis` 的外部题，同样按 `topicIds` | 诊断器实际索引 | **24** |
| 主知识点 | 只认 `primaryTopicId`，一个点一道题 | 本报告、题库结构分析 | **30** |

差别来自两处，各自都能单独辩护，但混着比就是错的：

1. **能不能诊断**。全库口径把 10241 道 tag-mapped、4045 道
   compound-reference、22 道 broken 也算进题量，而诊断器一道都抽不到。
   这是「0 缺口」的全部来源。
2. **关联点算不算数**。复合题同时标了 3 个知识点，按 `topicIds` 计
   等于一道题给三个点各算一道。诊断时确实三个点都可能抽到它，
   但「这个点有 8 道题」的说法会失真——那 8 道可能是同一批复合题。

结论：**全库口径没有错，它回答的是「题库资产有多少」；
错的是拿它回答「诊断够不够用」。**

### 三、踩出来的 bug：诊断池漏掉自有题

第一版把诊断池写成：

```python
usable = [q for q in allq if q.get("usable_for_diagnosis")]   # 错
```

自有题（`questions.json`）**没有这个字段**——它们本来就是诊断主库，
不需要自己声明准入。结果 2235 道自有题整段被过滤掉，
小学「诊断池题量不足」从 24 虚报成 **169 个点**。

这个 bug 不抛异常、不缺字段、测试全绿，只是数字悄悄变坏。
正确写法：

```python
usable = list(own) + [q for q in ext if q.get("usable_for_diagnosis")]
```

`tests/test_stage_policy_accounting.py` 里那条
`test_usable_pool_contains_own_questions` 就是专治它的：
断言诊断池题点对 ≥ 自有题在该段的题点对。

### 四、顺带证伪的三条旧结论

| 旧说法 | 实测 | 性质 |
|---|---|---|
| 三学段题量下限 0 缺口 | 诊断池 24 / 41 / 19；主知识点 30 / 50 / 45 | 口径错 |
| 小学单一难度点只剩 17 个 | 全库 17，诊断池 **87** | 口径错 |
| 小学 numeric 只占 0.12，远低于 0.5 目标 | 诊断池 **0.595**，已超标；真正缺的是简答（2.2% vs 15%） | **结论方向反了** |

第三条尤其值得记：同一个「不达标」的结论，换口径后变成「超额完成」。
这说明目标值本身也要绑口径——否则会一直朝着一个不存在的缺口做补题。

### 五、改法

1. `check_stage_policy.py` 同时输出两套账（全库 / 诊断池），
   题量、题型种类、难度档数、题型配比、难度分布全部成对；
   主函数拆成 `build_report()`（纯函数，可测）+ `render()`。
2. `stage_policy.json` 顶部加 `_口径` 说明，写死三个口径的定义与当前值。
3. 新增 `tests/test_stage_policy_accounting.py`（5 条）：
   诊断池 ⊆ 全库、池子变小缺口只增、自有题必须在内、两套账键齐全、
   **策略文件里的数字不许漂移**（这条会让过期文档直接测试失败）。
4. 修 4 处已漂移的数字：上海中考 117→764、小学→初中 2→14 条边、
   小学无可诊断 132→133、高中可诊断 6426→7700。
5. `engine.py` 里「standard 覆盖只有 20%（94/477）」的注释已过期：
   **开外部后**实测 60.8%（290/477），**已达到 STEP_UP_MIN_STANDARD_COVERAGE=0.6**；
   只算自有题是 14.3%（68/477）。开关仍保持 False——旧实验的负结论是在 20% 覆盖的库上跑的，
   条件变了，要重开必须先用 `ladder_experiment_real.py` 复跑，
   不能看到 0.608 > 0.6 就打开。

### 六、元教训

**一个不写口径的「0 缺口」比一个写得难看的「24 个点不足」危险得多。**
后者会让人继续查，前者会让人停止检查——而这轮所有真问题，
都是靠「这个 0 看起来太漂亮」才被翻出来的。

## D39. 四项待决事项的实测：三个结论被数据推翻

完整的分析与建议写在 `docs/decision-memo-2026-10-26.md`。这里只记录
**会改变后续判断的事实**，不重复论证过程。

### 一、外部题的收益比想象中薄

自有 2235 题 → 全开 11240 题，三档准确率只从 69.2% 涨到 71.3%（+2.1pp）。
用 `tools/key_error_sensitivity.py` 注入答案键噪声：

- 错误率 2%：收益剩 +0.7pp
- 错误率 3%：收益 0.0
- 错误率 8%：-0.3pp

外部题没有 `verify`，准入只做到「答案与解析互证」，真实错误率未知。
所以**外部题的价值主要在覆盖（139→19 个高中不足点），不在准确率**；
上线前必须抽 200 道复核，按 ≤2% 设门槛。

### 二、升档复跑：收益是真的，代价也是真的

`tools/ladder_ab.py`，20 种子配对（同一 seed 同一批学生）：

| 学段 | 漏诊 | 根因命中 | 题量 |
|---|---|---|---|
| 全学段 | -1.04pp（显著） | -2.55pp（不显著） | +0.87 |
| 小学 | -0.63pp | **-4.22pp（显著）** | +0.58 |
| 高中 | -1.33pp | **-5.53pp（显著）** | +1.12 |

根因下降的机制是把「basic 对、standard 错」判成了 `shaky`，而 `shaky`
又被当成「上游也不稳」的证据，把根因推得更远。这不是难度校准的问题，
是**判定语义**的问题。

另外两个发现：

1. `DESCEND_ON_HARDER_FAILURE` 是**死开关**。它所在的 `else` 分支只在
   `first_correct == False` 时到达，`harder_failed` 恒为 False；B/C 两组
   实验结果逐位相同。真正「升档题答错」的路径在 `attempt >= max_attempts`
   分支，那里没有这个保护。
2. 全局覆盖率门槛是错的形状。开外部后全库 60.8% 过线，但小学 49.3%、
   初中 47.2%、高中 88.4%——高中把平均数拉过线，升档在小学/初中一半的点上
   不生效，正是注释里说要避免的不一致。

### 三、smse 的结构作用被低估了

763 道不是「一批可有可无的真题」：去掉它，初中不足点 41→64（缺 124 道题），
无 short 的点 79→114，蒙对率 0.126→0.180。它是初中**短答/数值题型的唯一来源**，
虽然 95% 是 basic、不提供难度阶梯。

更微妙的耦合：去掉 smse 后全库 standard 覆盖率从 60.8% 掉到 58.9%，
**刚好跌破升档门槛**。一个许可未声明的数据源，是升档门槛唯一能达标的原因。

结论：隔离必须做，但不能只隔离不替换；替换成本约 124–140 道初中题。

### 四、小学题型配比：四种口径，四个数

| 口径 | numeric | choice | short |
|---|---|---|---|
| 全库题点对 | 0.068 | 0.278 | 0.654 |
| 诊断池题点对 | 0.514 | 0.467 | 0.019 |
| 诊断池按题 | 0.595 | 0.384 | 0.022 |
| 模拟实际抽到 | 0.462 | 0.462 | 0.077 |

## D40. 外部题不再靠"来源可信"，改按证据分级

完整论证见 `docs/decision-memo-2026-10-26b.md`。这里只记会改变后续判断的结论。

### 一、`cross-checked` 曾经是空的

9005 道可诊断外部题全部标 `cross-checked`，理由写作「原卷答案与解析互相印证」。
实测：smse 763 道里，答案文本真的出现在解析里的只有 **57 道（7.5%）**；
cmm 62%、gaokao 78%。这句话描述的是导入时的动作，不是题目现在的证据。

五级证据（`cnkg/evidence.py`）实测分布：

| 等级 | 数量 | 占比 |
|---|---|---|
| verified（可复算） | 473 | 5.3% |
| corroborated（跨源同题） | 216 | 2.4% |
| explained（推导+结论一致） | 6513 | 72.3% |
| bare（只有答案） | 1797 | 20.0% |
| broken | 6 | 0.07% |

**独立证据合计 689 道 = 7.6%。** 这是必须先说清的前提，
否则"题库有 9005 道可诊断题"会被读成"有 9005 道可信题"。

### 二、判据先被自己的数据证伪三次

1. 逐条复算抓出 347 道"错误"，**全是假阳性**：解析里的连等式
   `12×63÷36=756÷36=21` 被截成 `12*63/36=756`。改为连等式整体求值后归零。
2. `2²` 在数据里被展平成 `22`，会让正确连等式算不通。
   **所以复算矛盾永不作为封存依据**，只记信号。
3. 反问题（「下列说法错误的是」）会让「故 A 正确」被当成结论。
   现在反问题直接放弃字母信号。

真正靠文本对账抓出的 5 道确证问题，全是**解析与题干错配**
（题干问十进制进率，解析讲拼角）。查答案键查不出来。

### 三、错误答案的后果不对称，所以分级不是"能不能用"

- 会、答案错 → 判薄弱 → 回溯 → **根因跑偏**（代价最高）
- 不会、答案错 → 蒙对 → 判掌握 → 漏诊（代价较低，不影响路径）

规则：只有 verified / corroborated 有权判薄弱；explained 只能确认掌握；
bare 不进诊断。写进 `may_judge_weak` / `may_confirm_mastery`。

### 四、升档开关现在是空的，别再讨论"开不开"

自有题库 standard 覆盖 68/477 = **14.3%**，够不到 0.6 门槛。
实测 `--no-step-up` 与默认两次模拟**逐位相同**（三档 0.698 / 漏诊 0.005 /
根因 0.648 / 题量 6.74）。加证据门槛后含外部题覆盖 60.8% → **52.6%**，
门槛重新关上。

真正的问题不是开关，是"只问基础题"：**38/75 = 50.7% 的「只会基础」被判「掌握」**。
本轮改为在结论里分层（`mastery_level`），报告不再笼统说"已掌握"。

重开三条件：按学段覆盖率 ≥60%、修 `DESCEND_ON_HARDER_FAILURE` 死开关、
加 basic-only 判定。

### 五、smse 的缺口被高估了 5 倍

证据门槛已经挡掉 667/763 道 bare，只有 91 道进新池。
初中不足点 41 → 59（证据门槛）→ 64（隔离 smse）；smse 只贡献 **24 道**，
不是上一轮说的 124 道。工单见 `build/gap_junior.json`。

### 六、找到 TAL-SCQ5K-CN，但**没有导入**

MIT 许可、5000 道、小初高、每题带详细解题步骤、带知识点路径——内容正是缺的。
但它的知识点是竞赛体系（1503 个叶子），与本项目课本章节点不对齐：

**挂错知识点比没有题更糟**——诊断会拿数论题去测「1～5 的认识」。
所以先建映射表再导入；在此之前只作离线对照集。

## D41　TAL-SCQ5K-CN 改为「挑战层」导入：挂板块，不挂知识点

日期：2026-10-26

**代价**：1423 道小学题落在 `logic`（路由写的是「对应思想」「逻辑分析」，

- `2**15` 触发「幂次过大」闸门（指数上限 12），改成 `1024*32`；
- 平方差那条 `(100+3)(100-3)=100^2-3^2=…` 里括号积紧贴等号，

**教学口径上的一条经验**：勾股、三角函数、二次根式这三类题，

## D49　高中 144 个核心点补应用题：把「专业情境」写成可复算的算式

日期：2026-10-26

**问题**：小学、初中已经清零，剩下 144 个高中核心点没有一道 standard/advanced 题。
高中题的难点不在计算，而在两个地方：

1. **情境必须先讲清「量是什么」**。分贝、pH、震级、BMI、相关系数、
   条件概率——这些量本身带公式，不先交代定义，学生连要求什么都不知道。
   所以每道题的题干都比初中长，把「这个量怎么算」写进情境里。
2. **符号写不进复算**。解析里一旦出现 `√`、`sin`、`tan`、`lg`，
   算式抽取就断了，证据等级掉回 explained，整批写不进去。

**决定**：分五册写成 `tools/app_items/h1a..h5b.py`（14 个模块），
144 个点每点 1 道 standard + 1 道 advanced，共 288 道。
解析只用四则与乘方，遇到根号、三角、对数就换一种写法：

- **改问平方**：勾股、距离、方差、K² 一律问「平方是多少」，答案自然是整数；
- **用勾股数放大**：3、4、5 放大 10 倍得 30、40、50，直接写成 `5*10=50`；
- **先算已知幂再加减**：`2^3=8`、`2^5=32`，对数题写成 `3+5=8`；
- **给近似值但要求精确乘**：`tan30≈0.577` 就写 50 乘 0.577，答案 30.35 与算式严格相等；
- **端点处做验算**：`169/13=13`、`56/7=8` 这类「解出未知数」的题，
  末步用除法把答案验回去。

**这一轮被机器拦下的六处**（都值得记住）：

1. `verify` 里写 `2^3` 会被当成异或，必须写 `2**3`（解析里写 `^` 没问题）；
2. 末步之后再补一句「回代检验 6-6=0」，最后一处成立的值会落到 0 上——
   **验算要放在答案之前**；
3. 分段/统计题里「先算中间量、再相加」的两个算式只写前一个，
   证据等级就是 explained，**答案那一步必须写成带等号的完整算式**；
4. 小数近似相乘（`1/1.732`、`3/0.707`）与答案对不上，
   换成能整除的数据（余弦平方、二面角 60 度）；
5. `点 (0,0) 到 3x+4y-10=0 的距离` 与库里既有题**题干完全重复**——
   换数据（5x+12y-26=0）而不是换说法；
6. `C(n,2)=28` 这类「解出 n」的题，verify 要写 `56/7`，
   不能写 `8*7`（那只等于 28，是方程右边）。

**结果**：核心点应用题覆盖 165 → **309 / 309**，应用题 350 → 638 道
（347 standard / 291 advanced；627 verified + 11 explained）。
题库 2585 → 2873。测试改成「309 个点漏一个就红」，
`BatchPlacementTest` 补上高中模块名（`h5b` → 前缀 `mh5`）的映射。

## D50　初中讲解卡：`why` 从「为什么这样算」改成「这条法则凭什么成立」

日期：2026-10-26

**问题**：小学 46 张核心卡写完之后，初中 119 个核心点一张卡都没有。
真正动笔时发现不能照抄小学的写法：

小学的 `why` 回答的是「为什么这样算」——把 11 分成 1 和 10 再凑十，
理由是「凑满十好算」。初中前两章全是规则：符号法则、去括号变号、
乘方里括号的作用、等式性质。学生背得下口诀（「负负得正」「减号后面全变号」），
却答不出「凭什么」，一遇到变式（`-2^4` 与 `(-2)^4`、`3a-(2a-1)`）就散架。

**决定**：初中的 `why` 一律给一条**可推演的理由**，而不是重复步骤，也不是重复口诀：

- 有理数加法 → 「加法就是接着走」：同向叠加路程，反向互相抵消；
- 有理数减法 → 「减 b 就是加 (-b)」，于是减法不需要另一套法则；
- 有理数除法 → 「除法问的是里面有几个」，倒数是「一份占多少」，
  所以符号规律必然和乘法一致；
- 乘方 → 括号决定负号是不是底数的一部分，`(-2)^4` 里负号被乘了 4 次；
- 去括号 → 减去一个整体，等于把整体里**每一项**都减掉；
- 等式性质 → 天平两边同加同减，轻重关系不变；
- 点线面体 → 线动成面：雨刷每个位置都扫过一片新区域。

**已写**：七上 22 个核心点、22 张（`tools/teach_junior_{1,2}.py`）。
两批各 11 张，按册次顺序，`worked_example` 全部可复算。
抽查覆盖：数轴、相反数、加减乘除、乘方、列代数式、代数式的值、整式加减、
方程与等式性质、解方程、实际问题、立体与平面、点线面体、直线射线线段、
线段比较、角的概念、角的比较、余角补角。

**为什么不一次写完 119 个点**：口径要先立住再放量。
七上 22 张是模板——若「法则凭什么成立」这个落点不对，返工 22 张比返工 119 张便宜。

**顺带确认的一件事**：`teach_cards.py --check` 对初中卡同样只查
「引用真实、例题可验算、步骤 ≥3、`why` ≥30 字、识别信号 2–4 条」，
不查「讲得好不好」。质量仍靠模板与人工 review；
`review_status` 保持 `draft`，没有冒充已审。
