# 教师复核与小规模试点

目前全部新增单元和活动仍为 AI 初稿。程序验算、AI 交叉复核、教师判断、
学生实际表现分别记录。以下工具已经可用，但仓库没有收集真实教师或学生数据。

## 1. 先审核内容，再开展试点

运行：

~~~bash
python tools/review_packet.py --output build/review-packet.json
~~~

审核包包含当前单元与实践活动的完整内容、量规例答、内容 SHA-256 以及
待填写记录。由实际教师或学科专家核对数学正确性、成立条件、反例、
目标与任务对齐、答案和量规、年龄适用性、课堂可执行性。
审核者填写身份、日期、记录编号、逐项意见和批准/要求修订的结论。

~~~bash
python tools/review_packet.py --check build/review-packet.completed.json
~~~

检查器拒绝旧内容版本、AI 身份批准、缺少记录和未完成的批准项。
检查通过只代表记录符合结构与版本要求；维护者仍须核对真实身份及判断。
维护者通过代码评审把对应 review 写入资源的 teacher_review，并将
review_status 调为 reviewed；同时保留外部审核原始记录和 record_id。
这一操作不得由 AI 自行生成“教师批准”。后续修改题干、解释、量规或图形
会改变内容版本，必须重新审核。

审核包包括教学答案，供审核者使用，不应放到学生可访问的静态目录。

## 2. 以具体目标组织试点

每次选择一到两个已审核目标，先保留首次未看讲解的表现，再安排讲解、
练习和新的迁移任务。延迟复测建议另日开展；实际时间间隔必须记录。
项目活动保留草图、测量表、推导和修改说明，以过程量规评价。

教师应明确哪些题测概念理解、哪些测计算熟练、哪些测迁移，并记录
提示、同伴帮助、使用工具、缺席和退出等条件。过程题由教师按量规评阅；
可以抽取部分作品由另一位教师复评，讨论分歧。不能用自动判分填补过程证据。

本地服务会保存原始答案、规范化答案、题目与判分版本、呈现/提交/反馈
时间、讲解请求、重复题和复测间隔。请求过材料不证明读完；浏览器中
不同题号也不证明未在别处见过题。匿名浏览器标识只用于隔离记录，既不是
实名认证，也不能用来计算真实学生人数。

## 3. 导出并检查描述性数据

学生界面的“学习记录”可以恢复会话或导出当前浏览器的 JSON。通过
CNKG_LEARNING_DB 为正式试点指定独立数据路径，避免把开发测试混入试点：

~~~bash
CNKG_LEARNING_DB=var/pilot-learning.sqlite python web/server.py
python tools/pilot_report.py --input learning-records.json --output build/pilot-report.json
~~~

可以重复传入 --input 合并多个导出；同一会话去重。报告按内容/判分版本、
任务模式、材料请求、时间间隔与重复题分别统计。正确比例仅以可自动判分的
有效作答为分母；跳过、未开放反馈和过程题分别报告。不同版本不直接合并。
没有输入时报告明确输出 pending_data，不生成模拟成效。

仅凭这些日志不能报告真实学生人数、学习增益或因果效果。需要另行核实
样本来源、参与人数、任务条件、教师评分和缺失数据。设计难度标签保持
“待校准”，待真实目标对齐任务取得足够、可解释的作答证据后再讨论调整；
避免仅凭一道题的正确率或本系统模拟结果改成“已验证难度”。

## 4. 内容与学习记录分开维护

默认内容库为 build/kg.sqlite，可从源数据重建；学习库为 var/learning.sqlite，
重建内容不会删除学习历史。学习库路径禁止设在仓库 build/ 下。分享代码时
不提交 var/；备份/迁移服务时需要保留学习库和浏览器标识对应关系。
清除浏览器标识后不能自动认领原记录，应先从当前浏览器导出需要的记录。

新内容或判分代码与未完成会话不兼容时，服务保留旧记录并要求重新开始；
已完成结果保存当时快照，不按新规则重算。这个行为保证之后审核时能看到
学习者当时实际遇到的题和得到的反馈。
