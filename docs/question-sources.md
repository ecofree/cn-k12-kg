## 一、主源：CMM-Math

- 仓库：`hf-mirror.com/datasets/ecnu-icalk/cmm-math`（huggingface.co 直连不通，镜像可用）
- 许可证：**BSD-3-Clause**，允许商用，需保留版权声明
- 文件：`all_data.jsonl`，25.9 MB，28069 行
- 字段：`id / image / answer / solution / level / question / options / subject / analysis`

### 实测数字

| 指标 | 初中 | 高中 |
|---|---|---|
| 原始条数 | 6335 | 8521 |
| 无配图 + 有答案 | 2953 | 6494 |
| 去重后（工具输出） | **2766** | **6349** |
| 其中选择题 | 1387 | 3605 |
| 选项结构破损待修 | 124（9%） | 133（4%） |
| 有解析 | 100% | 98% |

- 分年级：七 1457 / 八 620 / 九 689。**九年级（中考主力）反而最少**，这是真实短板。
- 答案字母分布 A 296 / B 382 / C 377 / D 332，没有系统性偏向。
  —— 这一条特意核过：本项目 D19 那次事故就是选项重排把答案搞错，导致「一路选 B」的假象。
  外部数据同样要先查分布是否畸形，再看别的。
- 配图题占比高（`image` 非空的约 28%），纯文本管道解不了，已整条排除。

### 两个必须知道的数据缺陷

1. **`subject` 字段不可信**。样例里一道「已知 a=1,b=2,C=60°，求 c」的解三角形题，被标成 `解析几何`。
   这个字段不能当知识点用，连粗分类都不能全信。
2. **选项首项常丢 `A.` 前缀**。初中 9%、高中 4%，是原站 HTML 解析残留。
   `tools/fetch_question_bank.py` 已按行序补位，补不齐的记 `options_intact: false` 留给人工。

复现：`python tools/fetch_question_bank.py --stage junior`

## 二、有数据但不能直接用的源

### MM-Math（THU-KEG/MM_Math）
- 原 `skkegkai/MM-Math` 已重定向到此仓库，MIT，5901 行。
- 字段 `question / solution` **是英文机翻**（"As shown in the figure, in the known △ABC..."）。
- `year` 字段存的是年级（取值为 `eight`），不是年份；`knowledge` 只有 `level_1/level_2` 两级英文标签。
- 用途：它是「中考题 + 知识点双标签」，可用来**核对我们的映射结果**，但不能当题干来源。

### TAL-SCQ5K-CN（好未来）
- MIT，`TAL-SCQ5K-CN/{train,test}.jsonl`，共 5000 条，全部 `single_choice`。
- 结构是全库最好的一份：有 `knowledge_point_routes`（三级路径）、`difficulty` 0–4、`answer_analysis`。
- 但按 `competition_source_list` 判学段：小学 823、高中 735、**初中仅 185**，其余 3257 未标。
- 来源是迎春杯、希望杯、AMC 一类**竞赛真题**，不是课内同步或中考。
- 教训：结构漂亮不等于能用。我们要的是「课内知识点 + 常见题型」，竞赛题会系统性地高估难度。

### GaoKaoMath（FrankieYao/GaoKaoMath）
- MIT，`test.jsonl` 仅 124 行，英文翻译，字段有 `year / province / number / score`。
- 省份+年份+分值这个组合本来很适合做「考频统计」，可惜只有 124 条。

## 三、看起来能用、实际没数据的

### cheese233/gaokao-related-math
- README 声称爬了出卷网 3027 套高考数学卷，转成 `data/jsonl/problems.jsonl`，MathML→LaTeX。
- **实测：仓库里没有 `problems.jsonl`**。337 个文件里 332 个是配图，剩下是 README 和配置。
- 有价值的是**爬虫本身**（TypeScript + jsdom + mathml2，带断点续抓、每日增量）。
  如果以后要自己抓出卷网，这套代码是现成的参考。

## 四、免费网站：PDF 为主，不能直接变结构化题

实测能访问（HTTP 200）：`chujuan.cn`（组卷网/出卷网）、`jyeoo.com`（菁优网）、
`zujuan.com`、`shijuan1.com`（第一试卷网）、`21cnjy.com`、`zhongkao.com`、`51jiaoxi.com`。

| 站点 | 形态 | 免费程度 | 结构化程度 |
|---|---|---|---|
| 出卷网 chujuan.cn | 单题 + 解析，网页 | 免费可看，据其爬虫项目称高考数学 3027 套 | 中（MathML，需转 LaTeX） |
| 菁优网 jyeoo.com | 单题 + 解析 + 知识点导航 | 部分免费，解析常需登录 | 中高 |
| 21世纪教育网 21cnjy.com | 整卷，Word/PDF/图片 | 下载需点数 | 低 |
| 第一试卷网 shijuan1.com | 整卷压缩包 | 标「免费资源」 | 低（.rar 里是 doc/pdf） |
| 中考网 zhongkao.com | 整卷，多为图片版 | 免费浏览 | 极低（图片） |

**关键实测**：出卷网的初中数学试题列表页**没有知识点标签**，每题只标来源试卷和年份学期
（例：`2027九上·开江开学考`）。所以「抓下来就自带知识点」这个假设不成立。

另一个被推荐过的 **api.xuekubao.com**（宣称免费额度 + 结构化 JSON + 知识点出题）：
根路径实测返回 404，需要 `x-api-key` 才能调，**无法在不注册的情况下验证质量**。
它的商业模式是免费额度用完后按量付费，或买断源码。作为备选记录，不作为主路径。

## 五、中考到底有多分散（实测）

以 21世纪教育网「2025 年中考数学真题汇总」页为准（`/special/b311218/`）：

- 页面共列出 **118 条**资料条目
- 覆盖 **约 30 个省级行政区**（河北、浙江、新疆、陕西、湖北、河南、湖南、天津、山西、
  江西、福建、上海、云南、安徽、重庆、青海、辽宁、北京、内蒙古、广西、山东、江苏、
  四川、甘肃、贵州、吉林、广东、黑龙江等）
- 另有 **约 36 个地级市自主命题**（南京、扬州、苏州、连云港、青岛、烟台、淄博、威海、
  东营、成都、宜宾、德阳、眉山、遂宁、内江、凉山、广安、南充、达州、泸州、自贡、资阳、
  乐山、兰州、武威、嘉峪关、临夏、长春、长沙、深圳、广州、武汉、齐齐哈尔、绥化、龙东等）
- 118 条里大量是同地区多版本：含答案 / 无答案 / 扫描版 / 图片版 / A 卷 / B 卷

**推算（非实测）**：去重后一个年份大约 60–70 套不同的数学卷，
按每套 25 题算，**单年新增约 1500–1800 道题**。十年累积 1.5 万–2 万道。

所以用户的判断是对的：中考确实分散到「一城一卷」。
但这个分散对我们**不是坏事**——

> 我们不需要「收齐每个地区」，只需要「每个知识点至少 3 道题」。
> 分散意味着同一个知识点在不同地区有大量变体，正好解决
> 「364 个知识点只有 2 道题、一次诊断就耗尽题库」这个当前最大短板。

按这个目标，CMM-Math 一个源就够了，不必去啃 118 份 PDF。

## 六、真正的瓶颈：题 → 知识点

拿项目里 127 个初中知识点的**名称**，直接去 2766 道初中题里做检索：

```
命中 233 / 2766 = 8.4%
被覆盖知识点：25 / 127
零命中的例子：正数和负数、有理数的概念与分类、数轴、有理数的大小比较、乘方、列代数式…
```

原因很直接：题目不会写「本题考查有理数的加法」，它写的是
「若 a 表示一个有理数，且 |−3−a|=3+|a|，则 a 应该是（ ）」。
知识点名和题干之间本来就不同词。

那把粒度放宽到「章节」呢？用字符 2/3-gram + TF-IDF 质心分类器，
拿项目自己的 1077 道题（已有 topicId→章节 标注）做 5 折交叉验证，按 topicId 分组防泄漏：

| 设定 | 类别数 | top1 | top3 |
|---|---|---|---|
| A 全库直接判章 | 117 | 27.6% | 43.3% |
| B 只判是哪一册 | 23 | 35.8% | 60.6% |
| C 已知册，判册内哪一章 | 2–7 | **58.1%**（按题量加权） | — |

注意 B×C ≈ 20.8%，比 A 还低——**「先判册再判章」这个两级结构并不成立**，
因为很多册的内容本来就重叠（七上、八上都有数与式）。能用的只有 C。

C 的分册明细：

| 册 | 题量 | 章数 | 册内判章 top1 |
|---|---|---|---|
| 二下 | 26 | 4 | 30.8% |
| 七上 | 94 | 6 | 39.4% |
| 一上 | 63 | 5 | 42.9% |
| 八上 | 39 | 6 | 43.6% |
| 九上 | 37 | 6 | 48.6% |
| 六上 | 39 | 6 | 56.4% |
| **七下** | 60 | 6 | **71.7%** |
| **八下** | 38 | 6 | **78.9%** |
| **九下** | 36 | 4 | **77.8%** |
| 必修一 | 99 | 5 | 61.6% |
| 必修二 | 112 | 5 | 71.4% |
| 选必一 | 59 | 3 | 86.4% |

规律很清楚：**高中题好判（62–86%），小学初中题难判（31–49%）**。因为高中知识点自带术语
（导数、圆锥曲线、数列），而小学初中的题大多是一段生活场景 + 算术，彼此长得几乎一样。

**结论：字面/统计方法到此为止。**
58% 已经是在「已知是哪一册」的前提下、而且是在我们自己写的题干上测出来的上限；
换成真实中考题的措辞，只会更低。`tools/topic_classify.py` 保留下来当**预筛器**用
（把 40 个候选章缩到 3 个），但不能当自动标注器。

题到知识点的最终判定必须靠语义模型 + 人工抽检。这一步没法绕开，也不该假装能绕开。

复现：`python tools/topic_classify.py`（交叉验证）/ `--predict --stage junior`（给候选池预标）

## 七、落地方式

```bash
# 拉取并归一化（已跑通，输出到 inbox/candidates/）
python tools/fetch_question_bank.py --stage junior    # 2766 条
python tools/fetch_question_bank.py --stage senior    # 6349 条
python tools/fetch_question_bank.py --source gaokao   # 124 条

# 只看统计不落盘
python tools/fetch_question_bank.py --stage all --stats-only

# 章节分类可行性评估 / 给候选池预标
python tools/topic_classify.py
python tools/topic_classify.py --predict --stage junior
```

输出字段对齐 `data/questions.json`，但 `topicId: null`、`needs_kc: true`、
`review_status: unverified`——**外部题一律不进诊断数据**，与 D22「证据分层」一致。

下一步（按优先级）：

1. 先做**高中**：`cmm_senior.jsonl` 6349 道，字面判章能到 62–86%，可以半自动映射 + 抽检，
   而且高中 147 个知识点里也有大量只有 2 题的点；
2. 初中只在高置信区间自动落标：取 `topic_classify` 的第一名与第二名分差 > 0.05 的那部分，
   其余进人工/模型队列，别整批硬塞；
3. 选择题进库前必须重跑 `verify_questions.py` 的选项校验——**答案键事故（D19）的教训是现成的**；
   同时核一遍答案字母分布，CMM 是 A296/B382/C377/D332，进库后若分布突变，就是解析出了问题。
